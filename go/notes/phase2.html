P2

Generics (Go 1.18+)

Theory

Type Parameters

  • func F[T any](v T) T — T is a type parameter
  • Square brackets after function/type name
  • Type inferred at call site usually
  • Can be on functions AND types (structs)

Constraints

  • any — any type (no operations allowed)
  • comparable — supports == and !=
  • constraints.Ordered — supports <, > etc.
  • ~int — int or any type with underlying int
  • Interface as constraint: must have specific methods

When to Use

  • ✅ Generic data structures (stack, queue, set)
  • ✅ Generic algorithms (Map, Filter, Reduce)
  • ✅ Replace repetitive type-specific code
  • ❌ Not for runtime polymorphism — use interfaces
  • ❌ Don't over-generalize: wait until needed
Code Examples
// ── Generic function ──────────────────────────────
func Map[T, U any](s []T, f func(T) U) []U {
    result := make([]U, len(s))
    for i, v := range s { result[i] = f(v) }
    return result
}
nums := []int{1, 2, 3}
doubled := Map(nums, func(n int) int { return n * 2 }) // [2, 4, 6]
strs := Map(nums, strconv.Itoa)                         // ["1", "2", "3"]

// ── Generic type (stack) ──────────────────────────
type Stack[T any] struct { items []T }
func (s *Stack[T]) Push(v T)      { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
    var zero T
    if len(s.items) == 0 { return zero, false }
    n := len(s.items) - 1
    v := s.items[n]
    s.items = s.items[:n]
    return v, true
}

intStack := Stack[int]{}
intStack.Push(1); intStack.Push(2)

// ── Constraints ────────────────────────────────────
type Number interface { ~int | ~int64 | ~float64 }

func Sum[T Number](nums []T) T {
    var total T
    for _, n := range nums { total += n }
    return total
}

// ── Union constraint with ~ (underlying type) ──────
type MyInt int
Sum([]MyInt{1, 2, 3}) // works! ~int matches MyInt
⚠️ Gotchas
Generics add complexity — only add when the benefit is clear. Don't make everything generic just because you can.
Cannot use generic types as map keys with any constraint — need comparable constraint to use as map key or with ==.
Zero value of type param — use var zero T to get the zero value. You can't use nil unless T is constrained to allow it.
Interview Q&A
When should you use generics vs interfaces?
Use interfaces for runtime polymorphism (passing different types that share behaviour at runtime). Use generics for compile-time type safety on algorithms/data structures where you want to avoid code duplication without sacrificing type info. Generics eliminate the need for type assertions; interfaces support dynamic dispatch.
What does the ~ (tilde) operator mean in type constraints?
~T means "T or any type whose underlying type is T". So ~int matches int, type MyInt int, type UserID int, etc. Without ~, only the exact type matches.

Context Package

Theory

What is Context?

  • Carries deadlines, cancellation signals, and request-scoped values
  • Passed as first argument: func F(ctx context.Context, ...)
  • Forms a tree: child inherits parent's deadline/cancel
  • Cancelling parent cancels all children

Types

  • context.Background() — root, never cancels
  • context.TODO() — placeholder when unsure
  • context.WithCancel(parent) → (ctx, cancelFn)
  • context.WithTimeout(parent, d) — deadline from now
  • context.WithDeadline(parent, t) — absolute time
  • context.WithValue(parent, key, val) — carry values

5 Rules

  • 1. Always first parameter, never in struct
  • 2. Never pass nil context — use Background/TODO
  • 3. Always call cancel() — prevents goroutine leaks
  • 4. Context values for request-scoped data only
  • 5. Check ctx.Done() in long-running loops
Code Examples
// ── WithTimeout — most common ─────────────────────
func fetchUser(ctx context.Context, id int) (*User, error) {
    ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
    defer cancel() // ALWAYS defer cancel to prevent leaks

    req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        if errors.Is(err, context.DeadlineExceeded) {
            return nil, fmt.Errorf("fetchUser: timeout: %w", err)
        }
        return nil, err
    }
    defer resp.Body.Close()
    // ...
}

// ── WithCancel — manual cancellation ─────────────
func worker(ctx context.Context) {
    for {
        select {
        case <-ctx.Done():
            fmt.Println("worker stopped:", ctx.Err())
            return
        default:
            doWork()
        }
    }
}

ctx, cancel := context.WithCancel(context.Background())
go worker(ctx)
time.Sleep(5 * time.Second)
cancel() // stop the worker

// ── WithValue — request-scoped data ─────────────
type ctxKey string
const RequestIDKey ctxKey = "requestID"

ctx = context.WithValue(ctx, RequestIDKey, "req-123")
rid := ctx.Value(RequestIDKey).(string) // type assert
⚠️ Gotchas
Forgetting cancel() leaks goroutines — WithTimeout/WithCancel allocate resources. If cancel() is never called (even after timeout), the internal timer goroutine leaks. Always defer cancel().
Context values are not for function parameters — don't pass database connections, loggers, or function args via context. Only use for request-scoped metadata: request ID, auth user, trace ID.
Type the context key — use a custom unexported type for context keys to prevent collisions between packages. type ctxKey string instead of plain string.
Cancelled context error propagation — always check ctx.Err() or errors.Is(err, context.Canceled) to give meaningful error messages upstream.
Interview Q&A
Why must you always call the cancel function returned by WithTimeout?
Even if the timeout fires and the context is automatically cancelled, the internal timer goroutine is not released until cancel() is called. Failing to call cancel() causes a goroutine leak. Always: ctx, cancel := context.WithTimeout(...); defer cancel().
What should you store in context values?
Only request-scoped data that crosses API boundaries: request ID, trace ID, authenticated user identity, locale. Do NOT store function arguments, database connections, loggers, or anything that should be explicit in function signatures.

JSON, Time, Strings & Stdlib

Theory

encoding/json

  • json.Marshal(v) → []byte, error
  • json.Unmarshal(data, &v) — decode
  • json.NewEncoder(w).Encode(v) — streaming
  • Struct tags: json:"field,omitempty"
  • Unexported fields are ignored

time Package

  • Reference time: Mon Jan 2 15:04:05 MST 2006
  • time.Now(), time.Since(t), time.Until(t)
  • t.Format("2006-01-02") — custom format
  • time.Parse("2006-01-02", s)
  • time.Duration — nanosecond units

strings & strconv

  • strings.Contains/HasPrefix/HasSuffix
  • strings.Split/Join/TrimSpace/ToLower
  • strings.Builder — efficient string concat
  • strconv.Itoa/Atoi — int↔string
  • strconv.ParseFloat/ParseBool

Key Stdlib Packages

  • os — files, env vars, process
  • io — Reader/Writer/Closer interfaces
  • bufio — buffered I/O
  • net/http — HTTP client + server
  • sync — Mutex, WaitGroup, Once
  • math/rand/v2 (Go 1.22+)
Code Examples
// ── JSON ──────────────────────────────────────────
type User struct {
    ID        int       `json:"id"`
    Name      string    `json:"name"`
    CreatedAt time.Time `json:"created_at"`
    Internal  string    `json:"-"`          // always omit
    Bio       *string   `json:"bio,omitempty"` // omit if nil
}

u := User{ID: 1, Name: "Alice"}
data, _ := json.Marshal(u)
fmt.Println(string(data))

var decoded User
json.Unmarshal(data, &decoded)

// Streaming (preferred for HTTP):
json.NewEncoder(w).Encode(u)
json.NewDecoder(r.Body).Decode(&u)

// ── time ──────────────────────────────────────────
now := time.Now()
fmt.Println(now.Format("2006-01-02 15:04:05"))

t, err := time.Parse("2006-01-02", "2024-01-15")
fmt.Println(time.Since(t))

deadline := time.Now().Add(30 * time.Second)
time.Sleep(100 * time.Millisecond)

// ── strings.Builder (efficient concatenation) ─────
var sb strings.Builder
for i := 0; i < 100; i++ {
    sb.WriteString("word ")
}
result := sb.String() // single allocation

// ── strconv ───────────────────────────────────────
n, err := strconv.Atoi("42")
s := strconv.Itoa(42)
f, err := strconv.ParseFloat("3.14", 64)
b, err := strconv.ParseBool("true")
⚠️ Gotchas
The "mysterious" time format — Go uses the reference time Mon Jan 2 15:04:05 MST 2006 as a template. The numbers are fixed (month=1, day=2, hour=15, min=4, sec=5, year=2006). Use this exact reference, not strftime patterns.
json.Number for large numbers — by default, JSON numbers decode to float64 which loses precision for large int64. Use json.Decoder.UseNumber() for large IDs.
String concatenation with + in loops — creates a new string each iteration (O(n²)). Always use strings.Builder or fmt.Sprintf for loop concatenation.
time.Time is a value type — it's safe to copy. But time.Time{} is the zero time (Jan 1, year 1), not "not set". Use *time.Time or check t.IsZero().
Interview Q&A
Why does Go's time package use a specific reference date instead of format codes like %Y-%m-%d?
Go uses the reference time "Mon Jan 2 15:04:05 MST 2006" because each component has a unique value (month=01, day=02, year=2006, hour=15, min=04, sec=05). You format by showing how the reference time should look. It's more readable than memorizing strftime codes, but requires knowing the reference date.
How do you handle the omitempty tag with struct fields?
omitempty omits the field if it has its zero value: 0 for numbers, "" for strings, false for bool, nil for pointers/slices/maps. To optionally omit a struct field, make it a pointer (*int, *string) so nil = "not set".

Structured Logging (slog)

Theory

What is slog?

  • Standard library logger since Go 1.21
  • Structured: key-value pairs, not plain strings
  • JSON or text output handlers built-in
  • Levels: Debug, Info, Warn, Error
  • Replaces log package for production code

Key Features

  • slog.With(k, v) — add persistent attrs
  • slog.WithGroup(name) — namespace attrs
  • Logger is a value — embed in structs, pass around
  • Custom handlers (e.g., OpenTelemetry bridge)
  • Context-aware: slog.InfoContext(ctx, ...)
Code Examples
// ── Basic usage ───────────────────────────────────
slog.Info("user logged in", "user_id", 123, "method", "oauth")
slog.Warn("slow query", "duration_ms", 4500, "query", sql)
slog.Error("db failed", "error", err)

// ── JSON handler (production) ─────────────────────
logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
    Level: slog.LevelInfo,
}))
slog.SetDefault(logger) // make it the global default

// ── With — add persistent context ─────────────────
reqLogger := logger.With("request_id", "abc-123", "user_id", 42)
reqLogger.Info("processing request")  // always has request_id + user_id
reqLogger.Info("request complete", "duration_ms", 120)

// ── Context-aware ─────────────────────────────────
slog.InfoContext(ctx, "event", "key", "value")

// ── WithGroup — namespace ─────────────────────────
logger.WithGroup("db").Info("query", "sql", q, "rows", n)
⚠️ Gotchas
Odd number of key-value args — slog expects pairs: slog.Info("msg", "key", val). Odd count silently emits a !BADKEY attribute.
slog.Any for complex types — for non-primitive values, use slog.Any("user", u) to ensure proper marshalling.

Go Tooling — Test, Vet, Build, Generate

Theory & Cheatsheet

Testing Patterns

  • File: xxx_test.go, func: TestXxx(t *testing.T)
  • t.Errorf — fail but continue
  • t.Fatalf — fail and stop test
  • t.Run("name", func) — subtests
  • Table-driven tests: slice of structs

Benchmarks

  • Func: BenchmarkXxx(b *testing.B)
  • Loop: for i := 0; i < b.N; i++
  • go test -bench=. -benchmem
  • b.ResetTimer() — exclude setup time
  • Reports: ns/op, B/op, allocs/op

go:generate

  • //go:generate command args in source
  • go generate ./... — runs all directives
  • Common: mockgen, stringer, protoc, sqlc
  • Commit generated files to git
Code Examples
// ── Table-driven test ─────────────────────────────
func TestAdd(t *testing.T) {
    tests := []struct {
        name     string
        a, b     int
        expected int
    }{
        {"positive", 2, 3, 5},
        {"negative", -1, 1, 0},
        {"zeros", 0, 0, 0},
    }

    for _, tc := range tests {
        t.Run(tc.name, func(t *testing.T) {
            got := Add(tc.a, tc.b)
            if got != tc.expected {
                t.Errorf("Add(%d,%d) = %d, want %d", tc.a, tc.b, got, tc.expected)
            }
        })
    }
}

// ── Benchmark ─────────────────────────────────────
func BenchmarkAdd(b *testing.B) {
    for i := 0; i < b.N; i++ {
        Add(100, 200)
    }
}

// ── go:generate example ───────────────────────────
//go:generate stringer -type=Status
//go:generate mockgen -source=repo.go -destination=mocks/repo_mock.go

type Status int
const (
    Active Status = iota
    Inactive
    Banned
)

io.Reader / io.Writer

Theory

Core Interfaces

  • io.Reader: Read(p []byte) (n int, err error)
  • io.Writer: Write(p []byte) (n int, err error)
  • io.Closer: Close() error
  • io.ReadWriter: composed Reader+Writer
  • io.EOF — signal end of input (not a real error)

Key Functions

  • io.Copy(dst, src) — stream src to dst
  • io.TeeReader(r, w) — read AND write to w
  • io.LimitReader(r, n) — cap reads at n bytes
  • io.ReadAll(r) — read everything into []byte
  • io.Discard — /dev/null equivalent
  • bytes.Buffer, strings.Reader — in-memory
Code Examples
// ── io.Copy — streaming (no full load into memory) ─
func uploadFile(dst io.Writer, src io.Reader) error {
    _, err := io.Copy(dst, src)
    return err
}

// Works with: files, HTTP bodies, buffers, network conns

// ── LimitReader — DoS prevention ──────────────────
http.HandleFunc("/upload", func(w http.ResponseWriter, r *http.Request) {
    // Limit request body to 10MB to prevent DoS
    limited := io.LimitReader(r.Body, 10<<20)
    data, err := io.ReadAll(limited)
    // ...
})

// ── TeeReader — read + log simultaneously ─────────
var debugBuf bytes.Buffer
tee := io.TeeReader(r.Body, &debugBuf)
json.NewDecoder(tee).Decode(&req) // reads from body AND writes to debugBuf

// ── Custom Reader ─────────────────────────────────
type CountingReader struct {
    r     io.Reader
    count int64
}
func (c *CountingReader) Read(p []byte) (int, error) {
    n, err := c.r.Read(p)
    c.count += int64(n)
    return n, err
}

// ── Pipe — connect writer to reader ───────────────
pr, pw := io.Pipe()
go func() {
    defer pw.Close()
    json.NewEncoder(pw).Encode(data)
}()
io.Copy(uploadDest, pr) // stream without buffering all in memory
⚠️ Gotchas
io.EOF is not an error — it signals successful end of input. After Read returns 0, io.EOF you're done. Don't return or log it as an error.
io.ReadAll reads everything into memory — fine for small payloads, dangerous for large ones. Use io.LimitReader + streaming for user-uploaded content.
Always close Readers/Writers — especially HTTP response bodies and files. Use defer r.Close(). Not closing leaks file descriptors and HTTP connections.
Interview Q&A
Why are io.Reader and io.Writer so important in Go?
They're the fundamental I/O abstractions. Any source of bytes (file, network, buffer, string, gzip, crypto) implements Reader; any sink implements Writer. Functions accepting these interfaces work with any I/O source/sink without knowing the concrete type — enabling composition (TeeReader, LimitReader, bufio.Scanner, etc.).

Reflection & Custom JSON

Theory

reflect Package

  • reflect.TypeOf(v) — returns Type
  • reflect.ValueOf(v) — returns Value
  • Type.Kind() — underlying kind (Struct, Ptr, Slice...)
  • Can inspect struct fields, tags, methods
  • Can set values via Value.Set() (must be addressable)

Custom JSON

  • Implement json.Marshaler: MarshalJSON() ([]byte, error)
  • Implement json.Unmarshaler: UnmarshalJSON([]byte) error
  • Use for: custom formats, Unix timestamps, enums
  • Always validate in UnmarshalJSON

When NOT to use reflect

  • ❌ Hot paths — 10-100x slower than direct access
  • ❌ When generics or interfaces work
  • ✅ ORMs, validators, JSON encoders
  • ✅ Debug/testing utilities
  • ✅ Serialization frameworks
Code Examples
// ── Custom JSON marshaling ─────────────────────────
type UnixTime time.Time

func (t UnixTime) MarshalJSON() ([]byte, error) {
    return []byte(strconv.FormatInt(time.Time(t).Unix(), 10)), nil
}

func (t *UnixTime) UnmarshalJSON(data []byte) error {
    var unix int64
    if err := json.Unmarshal(data, &unix); err != nil { return err }
    *t = UnixTime(time.Unix(unix, 0))
    return nil
}

// ── Struct tag inspection ──────────────────────────
type User struct {
    Name string `json:"name" validate:"required,min=2"`
}

func getTags(v any) {
    t := reflect.TypeOf(v)
    if t.Kind() == reflect.Ptr { t = t.Elem() }
    for i := 0; i < t.NumField(); i++ {
        f := t.Field(i)
        fmt.Printf("Field: %s, json: %s, validate: %s\n",
            f.Name, f.Tag.Get("json"), f.Tag.Get("validate"))
    }
}

// ── reflect.DeepEqual in tests ────────────────────
if !reflect.DeepEqual(got, want) {
    t.Errorf("got %+v, want %+v", got, want)
}
⚠️ Gotchas
reflect is slow — avoid in hot paths. Profile first. Frameworks use reflect at startup and cache results.
Panic on non-addressable values — Value.Set() panics if the value isn't addressable. Pass a pointer and dereference: reflect.ValueOf(&x).Elem().
Custom UnmarshalJSON must handle all cases — JSON null, wrong type, invalid values. Always validate. Never trust user JSON input.
