Terminal & Shell (Bash/Zsh) Essentials

Navigation & Files

  • pwd — Print Working Directory. Shows the full path of where you currently are.
  • ls -la — LiSt files. -l long format (permissions, size, date), -a includes hidden files (starting with .).
  • cd dir — Change Directory. cd .. goes up one level. cd - jumps back to your previous directory (toggle).
  • mkdir -p a/b/c — MaKe DIRectory. -p creates parent dirs if missing, so the whole tree is built in one shot.
  • touch file.txt — Creates an empty file. Also updates the last-modified timestamp if the file already exists.
  • cp -r src/ dst/ — CoPy files. -r (recursive) is required when copying directories and everything inside them.
  • mv old new — MoVe or rename. Same command for both — moving within the same directory just renames.
  • rm -rf dir/ — ReMove. -r recursive (for dirs), -f force (no prompts). ⚠️ Irreversible — double-check path first.
  • ln -s target link — Create a symbolic link (shortcut/alias). Useful for pointing to files in other locations without copying.

View & Search

  • cat file — dumps the entire file to terminal. Best for short files.
  • less file — opens file in a scrollable pager (arrow keys, / search, q quits). Use for long files.
  • head -n 20 file — shows the first 20 lines. tail -n 20 shows last 20.
  • tail -f log — follow mode. Streams new lines as they're written. Essential for watching live log files.
  • grep -r "pattern" . — Global Regular Expression Print. -r searches recursively through all files from current dir.
  • find . -name "*.go" — finds files matching a name pattern starting from . (current dir). Also supports -type, -size, -mtime.
  • fzf — interactive fuzzy finder. Type parts of a name, it filters live. Pipe anything into it: history | fzf. ⭐
  • rg "pattern" — ripgrep, a modern, 10x faster grep. Respects .gitignore by default.
  • wc -l file — Word Count. -l counts lines, -w words, -c bytes.
  • diff a b — shows the line-by-line differences between two files.

Processes & System

  • ps aux | grep go — lists all running processes (a all users, u user-readable, x incl. no terminal) and filters those containing "go".
  • top — live process monitor (CPU, memory). Press q to quit.
  • htop — prettier, colored, interactive version of top. Arrow keys + F9 to kill a process.
  • kill PID — politely asks process to terminate (SIGTERM). kill -9 PID = force kill (SIGKILL), use only when normal kill fails.
  • lsof -i :8080 — LiSt Open Files. Shows which process is listening on port 8080. Gold for "port already in use" errors.
  • df -h — Disk Free. Shows disk usage per mounted filesystem. -h = human-readable (MB/GB).
  • du -sh * — Disk Usage. -s summary per item, -h human-readable. Shows size of each file/folder in current dir.
  • free -h — shows RAM usage (Linux). On Mac use vm_stat or Activity Monitor.
  • uname -a — prints all OS/kernel info (OS name, hostname, kernel version, architecture).

Network

  • curl -X POST url -d '{}' — sends an HTTP POST request with a JSON body. -X specifies method, -d sends data.
  • curl -v url — verbose mode. Prints the full request/response including headers — great for debugging APIs.
  • wget url — downloads a file from a URL to disk. Simpler than curl for pure downloads.
  • ping host — sends ICMP packets to test if a host is reachable and measure latency.
  • dig example.com — DNS lookup tool. Shows A, CNAME, MX records. Modern replacement for nslookup.
  • netstat -tulpn / ss -tlnp — list listening ports and the processes bound to them. ss is the modern tool.
  • ssh user@host — opens an encrypted remote shell on another machine.
  • scp file user@host:/path — Secure CoPy. Copies files over SSH between local and remote.
  • jq '.key' — command-line JSON processor. Parse, filter, transform JSON: curl ... | jq '.users[0].name'. ⭐

Pipes, Redirects, Chaining

  • cmd1 | cmd2 — pipe: sends stdout of cmd1 as stdin to cmd2. Enables composition, e.g., cat log | grep ERROR | wc -l.
  • cmd > file — redirect stdout to file, overwriting it.
  • cmd >> file — redirect stdout and append to file (doesn't overwrite).
  • cmd 2>&1 — redirect stderr (fd 2) into stdout (fd 1). Use when piping both error + normal output together.
  • cmd1 && cmd2 — runs cmd2 only if cmd1 succeeds (exit code 0). Chaining on success.
  • cmd1 || cmd2 — runs cmd2 only if cmd1 fails. Useful for fallbacks.
  • $(cmd) — command substitution: replaces itself with cmd's output, e.g., echo "today is $(date)".
  • xargs — takes stdin lines and turns them into arguments for another command, e.g., find . -name "*.log" | xargs rm.

Env & Shell Config

  • export VAR=value — sets an environment variable that child processes inherit. Without export, it's shell-local only.
  • echo $PATH — prints the PATH env var (list of dirs searched for executables). Prefix any var with $ to read it.
  • which go — prints the absolute path of the go executable the shell will run.
  • type cmd — tells you what cmd is: an alias, builtin, function, or file on PATH.
  • ~/.zshrc / ~/.bashrc — your shell's startup config file. Put aliases, exports, and PATH edits here.
  • source ~/.zshrc — re-reads the config into current shell without needing to restart.
  • alias gs='git status' — creates a shortcut. Typing gs now runs git status.
  • Oh My Zsh ⭐ — framework on top of zsh with themes, plugins, autocompletion. Install for a huge productivity boost.

Git — Daily Commands (MOST IMPORTANT)

Basics

  • git init — turns the current folder into a new Git repo by creating a hidden .git/ directory.
  • git clone url — downloads an existing remote repo to your machine, with full history.
  • git status — shows which files are modified, staged, or untracked. Run this constantly.
  • git diff — shows line-by-line changes not yet staged. git diff --staged shows what's about to be committed.
  • git add . — stages all changes in current directory. git add file stages a specific file.
  • git add -p — patch mode: interactively stage individual chunks of a file. Great for splitting work into clean commits.
  • git commit -m "msg" — creates a snapshot of staged changes with a message.
  • git commit --amend — edits the most recent commit (message or contents). Don't use this on already-pushed commits.
  • git log --oneline --graph --all — compact visual history of all branches in a single screen.

Branches

  • git branch — lists local branches; the current one has a *.
  • git branch -d name — deletes a branch (refuses if it has unmerged work). -D force-deletes.
  • git checkout -b feature/x — creates a new branch and switches to it in one step.
  • git switch main — modern, clearer version of git checkout main for switching branches.
  • git merge branch — merges branch into your current branch, usually creating a merge commit.
  • git rebase main ⭐ — replays your commits on top of main, giving a clean, linear history (no merge commits).
  • git cherry-pick hash — copies a specific commit from another branch onto your current branch.

Remote & Sync

  • git remote -v — lists configured remote repos (usually origin) with their fetch/push URLs.
  • git fetch — downloads new commits from remote but doesn't touch your working branch. Safe.
  • git pull — fetch + merge in one. Updates your current branch with remote changes.
  • git push origin branch — uploads your local commits to the remote branch.
  • git push --force-with-lease — safer force-push: only overwrites remote if it hasn't changed since your last fetch.
  • git pull --rebase ⭐ — pull, but rebase local commits on top instead of merging. Keeps history linear.

Undo & Fix

  • git restore file — discards unstaged changes in a file, reverting it to the last commit.
  • git restore --staged file — unstages a file (removes from "to be committed") without losing changes.
  • git reset --soft HEAD~1 — undoes the last commit but keeps changes staged. Great for rewording commits.
  • git reset --hard HEAD~1 ⚠️ — nukes the last commit and all changes. Irreversible. Use carefully.
  • git revert hash — creates a new commit that undoes the changes of the given commit. Safe on shared branches.
  • git stash — temporarily saves uncommitted changes so you can switch branches. git stash pop brings them back.
  • git reflog ⭐ — shows a log of every HEAD move (even reset/rebase). Use it to recover "lost" commits.

Inspect & Blame

  • git show hash — displays full details and diff of a specific commit.
  • git blame file — shows who last modified each line of a file and in which commit. Great for tracking down context.
  • git log -p file — shows the full commit history with diffs for a specific file.
  • git bisect — binary-search tool to find the commit that introduced a bug. Mark good/bad commits and it narrows down.
  • git diff branch1..branch2 — shows what's different between two branches (or commits).

Workflow & Best Practices

  • Conventional commits: feat:, fix:, chore:
  • Always pull before push
  • Small, atomic commits
  • Rebase before merging PRs
  • Never force push to main
  • Use .gitignore properly

Vim — Survival Kit (you WILL need this)

Modes (Vim's biggest concept)

  • Esc — returns to Normal mode, where keys are commands (not typed text). Vim's default mode.
  • i — enters Insert mode (type text before cursor). a = append (after cursor).
  • v — Visual mode to select characters. V selects whole lines. Ctrl+v rectangular block selection.
  • : — Command mode for file operations like save, quit, replace.

Movement (in Normal mode)

  • h j k l — move cursor left / down / up / right. Faster than arrows once you're used to it.
  • w — jump forward one word. b — jump back one word.
  • 0 — go to start of line. $ — go to end of line.
  • gg — jump to top of file. G — jump to bottom.
  • :42 — jump directly to line 42.
  • Ctrl+d / Ctrl+u — scroll down / up half a page.

Editing (Normal mode)

  • dd — deletes (and cuts) the current line.
  • yy — yanks (copies) the current line to Vim's clipboard.
  • p — pastes clipboard after cursor. P pastes before.
  • u — undo last change. Ctrl+r — redo.
  • cw — change word: deletes from cursor to end of word and enters Insert mode.
  • . — ⭐ repeats your last action. Incredibly powerful once you think in motions.

Save & Quit (the famous problem)

  • :w — write (save) the file.
  • :q — quit. Refuses if there are unsaved changes.
  • :wq — save and quit in one command.
  • :q! — force-quit, discarding unsaved changes.
  • :x — save (only if changed) and quit. Slightly more efficient than :wq.

Search & Replace

  • /pattern — searches forward for pattern in the file.
  • n — jump to next match. N — previous match.
  • :%s/old/new/g — replace all occurrences of old with new in the file (% = whole file, g = global).
  • :%s/old/new/gc — same as above but c prompts to confirm each replacement.

Node.js, npm, pnpm & .npmrc

npm Basics

  • npm init -y — creates a package.json with default values (no prompts).
  • npm install pkg / npm i pkg — installs a package and adds it to dependencies.
  • npm i -D pkg — installs as dev dependency (only needed during development, e.g., testing tools).
  • npm i -g pkg — installs globally, making it available as a CLI tool system-wide.
  • npm uninstall pkg — removes a package from node_modules and package.json.
  • npm update — updates installed packages to latest allowed by semver. npm outdated lists packages needing updates.
  • npm run script — runs a script defined in package.json's scripts section (e.g., npm run build).
  • npx pkg — runs a package without installing globally. Downloads, runs, discards.

.npmrc (registry & auth config)

  • What it is: npm's config file controlling registries, auth tokens, install behavior. Lives at ~/.npmrc (user) or project root.
  • registry=https://registry.npmjs.org/ — default public npm registry URL.
  • @myorg:registry=https://npm.pkg.github.com/ — route scoped packages (like @myorg/thing) to a private registry (GitHub Packages here).
  • //npm.pkg.github.com/:_authToken=TOKEN — auth token for that private registry. Required to install private packages.
  • save-exact=true — installs pin exact versions (1.2.3 not ^1.2.3).
  • fund=false / audit=false — disable the "funding" message and vulnerability audit on install (cleaner CI logs).
  • engine-strict=true — fails install if Node version doesn't match engines in package.json.

Node Version Management

  • nvm — lets you install & switch between Node versions. nvm install 20 downloads v20, nvm use 20 activates it for the shell.
  • fnm ⭐ — Fast Node Manager, written in Rust. Much quicker than nvm, same API.
  • .nvmrc — a file at project root with a Node version. nvm use auto-picks that version.
  • Volta — manages Node, npm, yarn, pnpm versions per-project automatically. Cross-platform.

pnpm & yarn (faster npm alternatives)

  • pnpm ⭐ — uses a content-addressable store with hard links. Same deps installed once on disk, shared across projects. Much faster & smaller.
  • pnpm install — installs deps from package.json. pnpm add pkg adds a new one.
  • pnpm-workspace.yaml — declares multiple packages in a monorepo (first-class support).
  • yarn — older alternative, still widely used. Yarn Berry (v2+) uses PnP (no node_modules).
  • Bun — new JS runtime + package manager + bundler in one. Very fast, drop-in for most npm workflows.

package.json essentials

  • scripts — named shortcut commands you run with npm run <name>. Common: build, test, lint, dev.
  • dependencies — runtime deps shipped with your app. devDependencies — build/test tools, not needed in production.
  • engines.node — declares the Node version your app requires. Combine with engine-strict.
  • Semver ranges: ^1.2.3 = any 1.x.x ≥ 1.2.3 (minor+patch updates). ~1.2.3 = patch only. 1.2.3 = exact.
  • package-lock.json — records exact installed versions. Commit it — guarantees reproducible installs across team/CI.

Common Global Tools

  • typescript — the TS compiler (tsc). ts-node runs TS files directly without precompiling.
  • nodemon — watches files and restarts your Node app on every change. Huge dev-time productivity boost.
  • prettier — opinionated code formatter. eslint — static analyzer that catches bugs & style issues.
  • http-server / serve — one-command static file servers, perfect for testing a built frontend.
  • ngrok — exposes your local port over a public HTTPS URL. Essential for webhook testing.

SSH, Keys & Remote Access

SSH Keys

  • ssh-keygen -t ed25519 -C "email" — generates a new SSH keypair using the modern ed25519 algorithm with a comment (your email).
  • ~/.ssh/id_ed25519 = private key (never share). id_ed25519.pub = public key (give to GitHub/servers).
  • cat ~/.ssh/id_ed25519.pub | pbcopy — prints public key and copies to clipboard (Mac). Linux: use xclip.
  • Add the public key in GitHub → Settings → SSH Keys, or paste into ~/.ssh/authorized_keys on a server.
  • ssh-add ~/.ssh/id_ed25519 — loads the key into the ssh-agent so you don't have to re-enter passphrase every time.

Remote Commands

  • ssh user@host — opens an interactive shell on the remote host as user.
  • ssh -i key.pem user@host — uses a specific private key file (common with AWS EC2 .pem keys).
  • scp file user@host:/path — copies a file over SSH to a remote path.
  • rsync -avz src/ user@host:/dst/ — smart sync: -a archive (preserve perms), -v verbose, -z compress. Only transfers what changed.
  • ~/.ssh/config ⭐ — define host aliases (Host myserver) with user/port/key, then just ssh myserver.

tmux / screen (persistent sessions)

  • tmux new -s work — creates a new session named work. Survives terminal close & SSH disconnects.
  • Ctrl+b d — detaches from the session (leaves it running in background).
  • tmux attach -t work — reattaches to the work session later.
  • Ctrl+b " — splits the current pane horizontally (top/bottom).
  • Ctrl+b % — splits the pane vertically (left/right).

Docker CLI — Daily Commands Preview

Full Docker/K8s deep-dive is in Phase 9. These are the commands you'll use daily starting now.

Images

  • docker pull image:tag — downloads an image from Docker Hub (or another registry).
  • docker images — lists all images stored locally.
  • docker build -t name . — builds an image from a Dockerfile in current dir, tags it name.
  • docker rmi image — ReMove Image from local storage.
  • docker image prune — deletes dangling (unused) images to free disk space.

Containers

  • docker run -d -p 8080:8080 --name app image — runs image: -d detached (background), -p host:container port map, --name friendly name.
  • docker ps — lists running containers. docker ps -a shows all (incl. stopped).
  • docker logs -f container — streams container logs live (-f follow, like tail -f).
  • docker exec -it container sh — opens an interactive shell inside a running container (-i interactive, -t TTY).
  • docker stop / start / rm container — stop (SIGTERM), start (restart), rm (delete). Must stop before removing.
  • docker system prune -a ⚠️ — nukes all unused images, containers, networks, volumes. Frees lots of space.

docker-compose

  • docker compose up -d — starts all services defined in docker-compose.yml in detached mode.
  • docker compose down — stops and removes containers, networks. -v also removes volumes.
  • docker compose logs -f svc — follow logs of a specific service.
  • docker compose exec svc sh — open shell in a running service container.
  • docker compose ps — lists services in the current compose project and their status.

Modules & Project Setup

Initialize & Manage Modules

  • go mod init github.com/user/repo — creates a go.mod file declaring this folder a module. The path is the import URL others will use.
  • go mod tidy — adds missing imports to go.mod & removes unused ones. Run after every batch of edits.
  • go mod download — downloads all deps into the module cache ($GOPATH/pkg/mod) without building.
  • go mod vendor — copies all deps into a local vendor/ folder. Useful for air-gapped builds & reproducibility.
  • go mod why pkg — explains why a package is in your dependency tree. Great for trimming bloat.
  • go mod graph — prints the full module dependency graph (one line per edge). Pipe to grep for inspection.
  • go mod edit -replace=old=new — temporarily swap a dep with a fork or local path (debugging libs).
  • go mod verify — checks that downloaded deps match expected checksums in go.sum.

Adding / Updating Dependencies

  • go get pkg — adds pkg at latest version & updates go.mod/go.sum. Don't use this just to "install" — it modifies your module.
  • go get pkg@v1.2.3 — pins to a specific version (semver).
  • go get pkg@latest — bumps to latest tagged release.
  • go get -u ./... — upgrades all deps in the module to latest minor/patch.
  • go get pkg@none — removes a dependency.
  • go install pkg@latest — installs an executable binary into $GOBIN (default ~/go/bin). Use this for CLI tools, NOT for adding deps.

Workspaces (multi-module dev)

  • go work init ./moduleA ./moduleB — creates a go.work file linking multiple local modules so edits in A are seen by B without publishing.
  • go work use ./newModule — adds another module to the workspace.
  • go work sync — syncs workspace's build list back into each module's go.mod.
  • ⭐ Use case: developing a library + service together in a monorepo.

Building & Running Code

Run / Build

  • go run main.go — compiles to a temp binary & runs it. Fast for scripts/dev. Doesn't produce an output file.
  • go run ./cmd/api — runs an entire package (folder). Common pattern for multi-binary repos.
  • go build — compiles current package to a binary in current dir. Name = folder name (or main for main package).
  • go build -o myapp ./cmd/api — builds and writes binary as myapp. -o = output path.
  • go build ./... — builds every package in the module recursively. Fast sanity check before commit.
  • go build -race — compile with race detector (development only — adds overhead).
  • go build -ldflags="-s -w" — strip symbols + DWARF debug info → smaller binary (~30%).
  • go build -ldflags="-X main.version=v1.0" — inject values into vars at build time (versioning).
  • go build -tags=prod — build with build tags (conditional compilation).

Cross-Compilation ⭐

  • GOOS=linux GOARCH=amd64 go build — build a Linux x86_64 binary on your Mac (no Docker needed).
  • GOOS=darwin GOARCH=arm64 go build — Apple Silicon Mac.
  • GOOS=windows GOARCH=amd64 go build — Windows 64-bit.
  • CGO_ENABLED=0 go build — disables CGO → produces a fully static binary (no glibc). Essential for distroless/scratch Docker images.
  • go tool dist list — prints every supported GOOS/GOARCH combo.

Install Binaries

  • go install — compiles current package & copies binary to $GOBIN. Make sure $GOBIN is on your PATH.
  • go install github.com/user/tool@latest — installs a remote CLI tool globally without cloning. The Go way to install binaries.
  • which mytool — verify it landed on PATH.

Testing & Benchmarks

Run Tests

  • go test — runs all tests in current package.
  • go test ./... — runs tests in every package recursively. Standard CI command.
  • go test -v — verbose: prints each test name + log output, even on success.
  • go test -run TestLogin — runs only tests whose name matches the regex. Speeds up TDD.
  • go test -run TestLogin/case_a — runs a specific subtest (table-driven case).
  • go test -count=1 ./... — disables test caching. Force a full re-run.
  • go test -short — sets testing.Short() true so tests can skip slow paths.
  • go test -timeout 30s — kill tests running longer than 30s (CI safety).
  • go test -failfast — stop at the first failure instead of running all tests.

Race Detector ⭐

  • go test -race ./... — runs all tests with the race detector ON. Run before every PR if you use goroutines. Adds ~2× CPU + 5–10× memory.
  • go run -race main.go — race detect during dev too.
  • What it catches: unsynchronized concurrent access to shared variables — the #1 source of mysterious Go bugs.

Coverage

  • go test -cover — prints % coverage per package. Quick check.
  • go test -coverprofile=cover.out ./... — writes detailed coverage data to a file.
  • go tool cover -html=cover.out — opens a colored HTML report in your browser. Red = uncovered lines.
  • go tool cover -func=cover.out — text breakdown by function.

Benchmarks & Fuzz

  • go test -bench=. — runs all BenchmarkXxx functions. Reports ns/op + allocs.
  • go test -bench=. -benchmem — adds memory stats (B/op, allocs/op). Always use this.
  • go test -benchtime=10s — runs each benchmark for 10s instead of default 1s (more stable numbers).
  • go test -fuzz=FuzzParse — runs a fuzz test (Go 1.18+). Generates random inputs to find crashes.
  • go test -fuzz=. -fuzztime=30s — time-bounded fuzz run.

Code Quality & Inspection

Format & Lint

  • gofmt -l . — lists files with formatting issues. -w overwrites them. Run before every commit.
  • go fmt ./... — wraps gofmt for the whole module. Most editors do this automatically.
  • gofumpt -w . — stricter gofmt with extra rules. Many teams adopt this.
  • goimports -w . — runs gofmt + auto-adds/removes imports. Set this as your save-on-format tool.
  • go vet ./... — built-in static analyzer. Catches printf format bugs, lock-by-value, unreachable code. Always green before merge.
  • golangci-lint run ⭐ — meta-linter combining 50+ checks (errcheck, staticcheck, gosec, etc.). Industry standard. Configure in .golangci.yml.
  • staticcheck ./... — Dominik Honnef's deep checker. Subset is included in golangci-lint.
  • govulncheck ./... ⭐ — official vuln scanner. Reports CVEs in your imports. Run weekly + in CI.

Inspect & Document

  • go doc fmt.Println — prints docs for a symbol straight in terminal.
  • go doc -all fmt — full docs for an entire package.
  • go list ./... — lists every package in the module. Useful as input to other tools.
  • go list -m all — lists all module deps + versions actually used.
  • go list -m -u all — same, plus shows which deps have updates available.
  • go env — prints the entire Go environment (GOPATH, GOOS, GOMODCACHE, etc.).
  • go env -w GOPROXY=https://proxy.golang.org,direct — set env vars persistently.
  • go version -m mybinary — prints Go version + module info compiled into a binary. Forensics!

Code Generation

  • go generate ./... — runs //go:generate directives in source files. Used for mocks, protobuf, sqlc, stringer, etc.
  • Common pairs: mockgen (gomock), protoc-gen-go, sqlc generate, stringer.
  • //go:generate stringer -type=Status — example directive in your code.

Profiling, Debugging & Tracing

pprof — CPU & Memory ⭐

  • go test -cpuprofile=cpu.out -bench=. — captures a CPU profile during a benchmark.
  • go test -memprofile=mem.out -bench=. — captures a heap profile.
  • go tool pprof cpu.out — interactive shell. Type top, list FuncName, web (opens flame graph in browser).
  • go tool pprof -http=:8080 cpu.out — opens pprof's HTML UI directly. Use this.
  • For a live server: import net/http/pprof and hit http://host:port/debug/pprof/ for live profiles.
  • go tool pprof http://localhost:6060/debug/pprof/heap — sample a running app's heap.

Execution Tracer

  • go test -trace=trace.out — capture a goroutine/scheduler trace.
  • go tool trace trace.out — opens a beautiful timeline view of every goroutine, GC, syscall, network event. Best for finding scheduling/contention issues.

Debugger (Delve)

  • dlv debug ./cmd/api — start an interactive debug session.
  • dlv test — debug your tests.
  • dlv attach PID — attach to a running process.
  • Common keys inside dlv: b main.go:42 (breakpoint), c (continue), n (next line), s (step in), p var (print), goroutines, stack.
  • VS Code uses Delve under the hood — F5 just works once Delve is installed.

Build Inspection

  • go build -gcflags="-m" — shows escape analysis: which vars escape to heap. Optimization gold.
  • go build -gcflags="-S" — print Go assembly. Rare, but useful for hot paths.
  • go tool objdump -s main.main mybinary — disassemble a function from a built binary.

Useful Env Vars & Misc

Environment Variables

  • GOPATH — workspace root (default ~/go). Module cache + binaries live under here.
  • GOBIN — where go install puts binaries. Default: $GOPATH/bin. Add to $PATH.
  • GOOS, GOARCH — target OS/architecture for cross-compilation.
  • CGO_ENABLED=0 — disable C interop. Required for static binaries / scratch images.
  • GOPROXY — module download proxy (default https://proxy.golang.org,direct). Set off for offline.
  • GOSUMDB — checksum DB. off to disable (private/air-gapped envs).
  • GOPRIVATE=github.com/myorg/* — don't use proxy/sumdb for these paths. Required for private repos.
  • GOFLAGS — default flags applied to every go command (e.g., -mod=readonly).
  • GOMAXPROCS — max OS threads running Go code. Defaults to # CPUs. Tune in containers.
  • GOMEMLIMIT — soft memory limit (Go 1.19+). Helps GC behave in containers (set to ~80% of pod limit).

Hot-Reload & Dev

  • air ⭐ — file watcher that rebuilds + restarts your Go server on save. Configure via .air.toml.
  • reflex -r '\.go$' -- go run main.go — generic file-watcher alternative.
  • CompileDaemon — older alternative to air.

Cleanup & Cache

  • go clean — removes object files from the current package.
  • go clean -modcache — wipes the entire module download cache (~/go/pkg/mod). Frees a LOT of disk.
  • go clean -testcache — clears cached test results. Use when test caching gives false confidence.
  • go env GOCACHE — find your build cache dir.

Version & Update Go itself

  • go version — print installed Go version.
  • go version -m mybinary — version + module info embedded in any binary.
  • Manage Go versions: use asdf, g (stefanmaric/g), or just download from go.dev/dl.
  • go install golang.org/dl/go1.23@latest && go1.23 download — install a specific version side-by-side.

The Empty Interface & any (Tour of Go)

📘 Tour — The Empty Interfaceinterface{} / any · holds any type · fmt.Println signature
🎥 Empty Interface & any ExplainedAnthony GG
🎥 any vs Generics — when to use eachMatt Holiday

What & Why

  • interface{} (Go <1.18) and any (Go 1.18+ alias) hold a value of any type.
  • Used by fmt.Println(a ...any), json.Unmarshal, middleware maps, generic caches.
  • Trades compile-time type safety for flexibility — prefer Generics when types are known.
  • A variable of type any stores a (type, value) pair under the hood.

Gotchas

  • Comparing any values that hold non-comparable types (slices, maps) causes a runtime panic.
  • A typed nil ((*MyType)(nil)) assigned to any is not nil — the classic nil-interface trap.
  • Over-using any defeats Go's static typing. Reach for Generics or concrete types first.
  • Type-assert out of any with comma-ok: v, ok := x.(string) — never the panicking form in production.

AI Safety, Guardrails & Security

🎥 Guardrails — Defending LLM AppsPrompt injection, jailbreaks
🎥 OpenAI Moderation API in GoContent safety layer

⚠️ Threats to Defend

  • Prompt injection: user input hijacking system prompt
  • Jailbreaking: bypassing safety instructions
  • Data leakage: LLM revealing other users' data
  • Excessive agency: agent performing destructive actions
  • PII in prompts: send only anonymized data to LLMs

🛡️ Mitigations in Go

  • Input sanitization layer before every LLM call
  • OpenAI Moderation API on user inputs
  • Guardrails AI — output validation
  • Output parsing with strict Go struct unmarshalling
  • Allowlisted tools only — never dynamic eval
  • Audit log every LLM input/output
