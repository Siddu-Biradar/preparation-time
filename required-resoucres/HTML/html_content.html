HTML — From 0 to Advanced

A single-file, interview-grade reference for Frontend SDE2/SDE3 roles. Covers theory, code, gotchas, accessibility, performance, security, and the questions that actually get asked.

1. How the Browser Reads HTML Beginner

HTML is a declarative markup language. The browser parses bytes → characters → tokens → nodes → DOM tree. Alongside, CSS is parsed into the CSSOM. The two combine into the Render Tree, then Layout → Paint → Composite.

Key things to know for interviews:

  • HTML parsing is tolerant — it recovers from missing tags (unlike XHTML which is strict).
  • Parsing is incremental and streaming; the browser can start rendering before the full HTML is downloaded.
  • <script> without async/defer blocks parsing.
  • CSS blocks rendering (not parsing of HTML, but the render tree).
  • The preload scanner looks ahead in HTML to start downloading assets in parallel.
Interview Tip Be able to draw the critical rendering path on a whiteboard and explain why defer scripts preserve execution order but async doesn't.

2. DOCTYPE & Document Structure Beginner

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Page Title</title>
  </head>
  <body>
    <!-- content -->
  </body>
</html>

Why <!DOCTYPE html>?

It triggers standards mode. Without it, browsers fall into quirks mode, emulating 1990s bugs (e.g., box-sizing: border-box behavior on <table>, wrong width/height rules).

Why lang matters

  • Screen readers use it to pick pronunciation (English vs French).
  • Search engines use it for ranking / regional targeting.
  • Chrome's "translate this page" uses it.

Why the viewport meta is required

Without it, mobile browsers assume a 980px virtual viewport and shrink your page — breaking responsive design.

Gotcha <meta charset> must appear in the first 1024 bytes of the document, otherwise the browser re-parses and can corrupt already-parsed bytes. Always put it first inside <head>.

3. Elements, Tags & Attributes Beginner

Void (self-closing) elements

Cannot have children or closing tags: <br>, <hr>, <img>, <input>, <meta>, <link>, <source>, <track>, <wbr>.

Global attributes (work on all elements)

  • id — unique, used for anchors, labels, JS.
  • class — CSS/JS hook, space-separated.
  • style — inline CSS (avoid in production).
  • title — tooltip on hover (not accessible to keyboard users).
  • tabindex — focus order. 0 = natural, -1 = focusable via JS only, >0 = avoid.
  • contenteditable — makes element editable.
  • hidden — removes from rendering & accessibility tree.
  • draggable, spellcheck, translate, dir.
  • data-* — custom data, read via dataset.
<article data-user-id="42" data-role="admin">...</article>

// JS
const el = document.querySelector('article');
el.dataset.userId;   // "42"
el.dataset.role;     // "admin"
el.dataset.newThing = "x"; // sets data-new-thing
Gotcha — id vs name id must be unique in the document. Duplicate IDs won't throw an error, but getElementById returns the first one and ARIA references break silently.
Gotcha — Boolean attributes disabled, readonly, checked, required, autofocus are boolean. Their presence = true. disabled="false" is still disabled.

4. Text Content & Lists Beginner

Headings

Only one <h1> per page (ideally). Never skip levels for styling — use CSS instead.

Paragraphs & inline phrasing

  • <strong> — semantic importance (bold). vs <b> — stylistic only.
  • <em> — stressed emphasis (italic). vs <i> — alternate voice/term.
  • <mark> — highlight relevance.
  • <small> — side comments, legal text.
  • <del> / <ins> — deleted / inserted content.
  • <abbr title="..."> — abbreviation with expansion.
  • <time datetime="2025-10-01"> — machine-readable dates.
  • <code>, <kbd>, <samp>, <var>, <pre>.
  • <q> (inline quote) vs <blockquote> (block quote, with cite attr).

Lists

<ul> unordered list </ul>
<ol start="5" reversed type="A"> ordered </ol>
<dl>
  <dt>HTTP</dt>
  <dd>HyperText Transfer Protocol</dd>
</dl>
b/i/strong/em — classic interview Q <b> and <i> are presentational; they have no semantic weight for screen readers. <strong> and <em> carry meaning. Google/SEO and assistive tech prefer the semantic ones.

5. Links & Navigation Beginner

<a href="/about">Internal</a>
<a href="https://x.com" target="_blank" rel="noopener noreferrer">External</a>
<a href="mailto:me@x.com?subject=Hi">Email</a>
<a href="tel:+911234567890">Call</a>
<a href="#section-2">Jump</a>
<a href="/file.pdf" download="report.pdf">Download</a>

The rel attribute

  • noopener — prevents the new tab from accessing window.opener (security, tabnabbing).
  • noreferrer — also strips the Referer header (implies noopener).
  • nofollow, ugc, sponsored — SEO signals for search engines.
  • preload, prefetch, preconnect, dns-prefetch — resource hints (see Performance).
Gotcha — target="_blank" without rel Modern browsers default to noopener, but older ones don't. Always add rel="noopener noreferrer" when opening external sites in a new tab.

6. Images & Media Intermediate

<img src="hero.jpg" alt="Team celebrating launch"
     width="800" height="450"
     loading="lazy" decoding="async" fetchpriority="low">

Why always set width and height?

Browsers reserve space → prevents CLS (Cumulative Layout Shift), a Core Web Vital.

Responsive images

<img
  src="img-800.jpg"
  srcset="img-400.jpg 400w, img-800.jpg 800w, img-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="...">

<picture>
  <source type="image/avif" srcset="hero.avif">
  <source type="image/webp" srcset="hero.webp">
  <img src="hero.jpg" alt="...">
</picture>

Alt text rules

  • Meaningful image → describe its purpose (not "image of...").
  • Decorative image → alt="" (empty but present) so screen readers skip it.
  • Never omit alt — screen readers then read the filename.

Video & Audio

<video controls preload="metadata" poster="thumb.jpg" playsinline>
  <source src="video.webm" type="video/webm">
  <source src="video.mp4"  type="video/mp4">
  <track kind="captions" src="en.vtt" srclang="en" label="English" default>
  Your browser doesn't support video.
</video>
Gotcha — autoplay Browsers block autoplay unless the video is muted (or user has interacted). Also add playsinline for iOS Safari, otherwise it goes fullscreen.

7. Tables Intermediate

<table>
  <caption>Quarterly sales</caption>
  <colgroup>
    <col span="1" style="background:#f7f7f7">
  </colgroup>
  <thead>
    <tr><th scope="col">Region</th><th scope="col">Q1</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">APAC</th><td>$1.2M</td></tr>
  </tbody>
  <tfoot>
    <tr><th scope="row">Total</th><td>$5.8M</td></tr>
  </tfoot>
</table>
  • scope="col|row" — essential for screen readers.
  • Use <caption> for accessible table titles.
  • Use tables ONLY for tabular data. Never for layout.
Layout tables Using tables for page layout is a classic red flag in interviews. Modern layout = Flexbox / Grid.

8. Forms & Validation Intermediate

<form action="/login" method="POST" novalidate autocomplete="on">
  <fieldset>
    <legend>Sign in</legend>

    <label for="email">Email</label>
    <input id="email" name="email" type="email"
           required autocomplete="email"
           placeholder="you@example.com">

    <label for="pw">Password</label>
    <input id="pw" name="password" type="password"
           minlength="8" required autocomplete="current-password">

    <button type="submit">Sign in</button>
  </fieldset>
</form>

Input types to know

text, email, password, number, tel, url, search, date, datetime-local, month, week, time, color, range, file, hidden, checkbox, radio, submit, reset, button, image.

Constraint validation attributes

required, pattern, min, max, minlength, maxlength, step, type.

Form submission & FormData

form.addEventListener('submit', (e) => {
  e.preventDefault();
  const data = Object.fromEntries(new FormData(form));
  fetch('/login', { method:'POST', body: JSON.stringify(data) });
});

Useful elements

  • <label> — must wrap or use for; clicking label focuses input.
  • <fieldset> + <legend> — group related fields (required for radio groups).
  • <datalist> — autocomplete suggestions.
  • <output> — calculated result.
  • <progress>, <meter> — progress vs measurement (distinct!).
  • <select> + <optgroup>.
Gotcha — button default type Inside a form, <button> defaults to type="submit". A "Cancel" button without type="button" will submit the form.
Gotcha — autocomplete tokens Password managers need specific tokens: current-password, new-password, one-time-code, username. Wrong tokens break password autofill.
Gotcha — input number input[type=number] scrolls values on focus+wheel. Strips leading zeros. Doesn't fire change for partial inputs. For phone numbers use type=tel.

9. Block vs Inline vs Replaced Elements Beginner

CategoryExamplesBehavior
Blockdiv, p, section, headerTakes full width, starts new line, respects width/height.
Inlinespan, a, strongFlows with text, ignores width/height, respects horizontal margin/padding only for layout.
Inline-blockbutton, inputFlows inline but respects width/height.
Replacedimg, video, iframe, inputContent replaced by external resource; has intrinsic size.
Gotcha You can't put block elements inside inline ones per spec. <a><div>...</div></a> is valid in HTML5 (anchors can wrap blocks) but <span><div>...</div></span> is not. <p><div></div></p> → the <p> is auto-closed before the <div> (classic gotcha).

10. Semantic HTML5 Intermediate

Semantic tags describe meaning, not appearance. Benefits: accessibility, SEO, maintainability, browser reader-modes.

<body>
  <header>...site header, logo, primary nav...</header>
  <nav aria-label="Primary">...</nav>
  <main>                       <!-- only ONE per page -->
    <article>                   <!-- self-contained piece -->
      <header><h1>Title</h1></header>
      <section>                 <!-- thematic grouping -->
        <h2>Section heading</h2>
      </section>
      <aside>related links</aside>
      <footer>tags, author</footer>
    </article>
  </main>
  <footer>copyright, secondary nav</footer>
</body>

Key rules

  • <main>: exactly one, excludes repeated content like headers/footers.
  • <section>: needs a heading; otherwise use <div>.
  • <article>: self-contained, independently distributable (blog post, card, tweet).
  • <aside>: tangentially related (sidebar, pull-quote, ads).
  • <figure> + <figcaption>: images, diagrams, code snippets with captions.
  • <details>/<summary>: native disclosure widget (accordion).
  • <dialog>: native modal with backdrop + focus trap (when used with showModal()).
Classic Interview Q section vs div vs article?
<div> = no semantic meaning, pure styling hook. <section> = a themed chunk with a heading. <article> = independently meaningful content. If you could syndicate it via RSS, it's an article.

11. Document Outline & Headings Intermediate

  • One <h1> per page (the page's main title).
  • Don't skip heading levels (h2 → h4 is bad for a11y).
  • Inside <article>/<section>, you may restart with <h2>; modern screen readers still use flat level navigation.
  • Never pick heading size by styling — pick by hierarchy, style with CSS.

HTML5 is more than new tags — it's a platform:

  • Storage: LocalStorage, SessionStorage, IndexedDB, Cache Storage.
  • Network: Fetch, WebSocket, Server-Sent Events, WebRTC, Beacon.
  • Device: Geolocation, DeviceOrientation, Battery, Vibration, Clipboard.
  • Media: <video>, <audio>, MediaRecorder, Web Audio, getUserMedia.
  • Graphics: Canvas 2D, WebGL, WebGPU, SVG.
  • Workers: Web Workers, Service Workers, SharedWorker.

// localStorage (strings only!)
localStorage.setItem('user', JSON.stringify({ id: 1 }));
const u = JSON.parse(localStorage.getItem('user') || 'null');

// cross-tab sync
window.addEventListener('storage', e => {
  if (e.key === 'user') { /* another tab changed it */ }
});
Gotchas
  • LocalStorage is synchronous — large writes block rendering.
  • Stores only strings; you must JSON.stringify.
  • Accessible by any JS on the page → never store JWTs or secrets here (XSS leaks it).
  • storage event fires in other tabs, not the one that set the value.
  • Incognito mode may throw QuotaExceededError.

16. Drag & Drop API Advanced

<div id="item" draggable="true">Drag me</div>
<div id="drop">Drop here</div>

<script>
const item = document.getElementById('item');
const drop = document.getElementById('drop');

item.addEventListener('dragstart', e => {
  e.dataTransfer.setData('text/plain', 'payload');
  e.dataTransfer.effectAllowed = 'move';
});

drop.addEventListener('dragover', e => {
  e.preventDefault();              // REQUIRED to allow drop
  e.dataTransfer.dropEffect = 'move';
});

drop.addEventListener('drop', e => {
  e.preventDefault();
  const data = e.dataTransfer.getData('text/plain');
  drop.textContent = 'Dropped: ' + data;
});
</script>
Gotcha Without e.preventDefault() on dragover, the browser rejects the drop silently. This is the #1 bug with native DnD.

19. Template, Slot & Web Components Advanced

<template id="card-tmpl">
  <article class="card">
    <h3><slot name="title">Untitled</slot></h3>
    <p><slot></slot></p>
  </article>
</template>

<script>
class MyCard extends HTMLElement {
  constructor() {
    super();
    const tmpl = document.getElementById('card-tmpl').content;
    this.attachShadow({ mode: 'open' }).appendChild(tmpl.cloneNode(true));

}
customElements.define('my-card', MyCard);
</script>

<my-card>
  <span slot="title">Hello</span>
  Body text here
</my-card>
  • <template> — parsed but inert; its children aren't rendered until cloned.
  • Shadow DOM = encapsulated DOM + CSS (styles don't leak in/out).
  • Three specs: Custom Elements, Shadow DOM, HTML Templates.

20. iframe, sandbox & embedding Advanced

<iframe
  src="https://widget.example"
  loading="lazy"
  referrerpolicy="no-referrer"
  sandbox="allow-scripts allow-same-origin"
  allow="camera; microphone"
  title="Payment widget"></iframe>

sandbox tokens (omit to lock everything down)

  • allow-scripts — let JS run.
  • allow-same-origin — treat iframe as same origin.
  • allow-forms, allow-popups, allow-modals, allow-downloads, allow-top-navigation.
Security sandbox="allow-scripts allow-same-origin" together defeats the sandbox — the iframe can remove its own sandbox attribute. Pick one.

Cross-origin communication

// parent
iframe.contentWindow.postMessage({ type:'PING' }, 'https://widget.example');

// iframe
window.addEventListener('message', e => {
  if (e.origin !== 'https://parent.com') return; // ALWAYS check origin
  // handle e.data
});

21. Accessibility — ARIA, Roles & Landmarks Advanced

The 5 rules of ARIA

  1. If you can use a native element, use it. Native > ARIA.
  2. Don't change native semantics (don't put role="button" on <a>).
  3. All interactive ARIA controls must be keyboard operable.
  4. Don't role="presentation" or aria-hidden on focusable elements.
  5. All form inputs must have accessible names (label, aria-label, aria-labelledby).

Landmarks (navigation shortcuts for screen readers)

header/role=banner, nav, main, aside/complementary, footer/contentinfo, form, search, region.

Common ARIA attributes

  • aria-label / aria-labelledby — accessible name.
  • aria-describedby — extra description (e.g., error text).
  • aria-expanded — for disclosures/accordions.
  • aria-controls — references element being controlled.
  • aria-current — "page" for current nav link.
  • aria-live="polite|assertive" — announce dynamic updates.
  • aria-hidden="true" — hide from AT (keep visible).
  • role="alert", role="status", role="dialog".
<button aria-expanded="false" aria-controls="menu-1">Menu</button>
<ul id="menu-1" hidden>...</ul>

<div role="alert">Your password is incorrect.</div>

<a href="/dashboard" aria-current="page">Dashboard</a>

22. Accessible Forms Intermediate

  • Every input needs a visible <label>. Placeholder ≠ label.
  • Group radios/checkboxes in <fieldset> + <legend>.
  • Tie errors with aria-describedby + aria-invalid="true".
  • Use role="alert" or aria-live regions for async errors.
  • Don't rely on color alone to show errors (add icon + text).

23. Keyboard & Focus Advanced

  • All interactive elements must be reachable via Tab.
  • Visible focus ring — never outline: none without a replacement.
  • Use tabindex="0" to add custom elements to tab order; -1 for JS-only focus.
  • Never use tabindex > 0 — it breaks natural order.
  • Modals need focus trap + restore focus on close. <dialog> does this automatically with showModal().
  • Add a "Skip to main content" link as the first focusable element.

25. Responsive Images & Lazy Loading Advanced

  • loading="lazy" on <img> and <iframe> below the fold.
  • Don't lazy-load the LCP image — it delays it. Use loading="eager" fetchpriority="high".
  • Use decoding="async" so image decoding doesn't block the main thread.
  • Serve modern formats: AVIF > WebP > JPEG.
  • Use srcset + sizes for density and art direction.
  • Inline critical SVGs; lazy/async the rest.

26. Core Web Vitals — HTML's Role Advanced

  • LCP (Largest Contentful Paint, <2.5s): preload fonts & hero image, avoid render-blocking JS, use fetchpriority="high".
  • INP (Interaction to Next Paint, <200ms): split long tasks, use defer, hydrate lazily.
  • CLS (Cumulative Layout Shift, <0.1): always set width/height on media, reserve space for ads, avoid inserting content above existing content.
  • FCP: inline critical CSS, stream HTML, compress (gzip/brotli).
  • TTFB: server + CDN issue, but HTML: keep doc small, use <link rel="preconnect">.

27. Security — XSS, CSP, rel=noopener Advanced

XSS (Cross-Site Scripting)

Never inject user-controlled strings as HTML. Prefer .textContent over .innerHTML. Sanitize if HTML is required (DOMPurify).

Content Security Policy

<meta http-equiv="Content-Security-Policy"
      content="default-src 'self';
               script-src 'self' https://apis.google.com 'nonce-abc123';
               img-src 'self' data: https:;
               object-src 'none';
               base-uri 'self';
               frame-ancestors 'none';">

Other HTML-level protections

  • rel="noopener noreferrer" on external target="_blank" links (tabnabbing).
  • referrerpolicy="no-referrer" on sensitive links.
  • sandbox untrusted iframes.
  • autocomplete="off" for sensitive fields (OTP, credit card CVV).
  • Use type="password" (never type="text") for secrets.
  • Subresource Integrity on CDN scripts: <script src=".." integrity="sha384-..." crossorigin="anonymous">.
  • Mark cookies HttpOnly; Secure; SameSite=Lax/Strict (HTTP-layer but crucial).

29. Top Interview Questions (SDE2 / SDE3) Advanced

Q1. What is the difference between HTML and XHTML?
XHTML is HTML reformulated as strict XML: tags must be lowercase, all tags closed, attributes quoted, no missing tags. A single syntax error stops rendering. HTML5 is a superset that is lenient and also adds new elements + APIs.
Q2. Quirks mode vs standards mode?
Without <!DOCTYPE html>, browsers emulate legacy bugs for backward compatibility (quirks mode). Standards mode follows the modern spec. There's also "almost standards" mode differing mainly in inline image layout inside tables.
Q3. defer vs async vs module scripts?
Both are non-blocking. defer preserves order and runs just before DOMContentLoaded. async runs as soon as fetched — order is unpredictable. type="module" is deferred by default and supports import.
Q4. What triggers a reflow vs repaint?
Reflow = layout recomputation (changing geometry, adding/removing DOM nodes, resize). Repaint = pixel redraw without layout (color, visibility, outline). Composite-only properties (transform, opacity) skip both and run on the GPU.
Q5. What are semantic elements and why do they matter?
Elements whose name describes their meaning (article, nav, aside…). They help screen readers, search engines, and future maintainers. They also enable reader-mode and landmark navigation.
Q6. Difference between localStorage, sessionStorage, cookies, IndexedDB?
See the Web Storage table. Key points: cookies go with every request (4KB), localStorage is sync/persistent/large, sessionStorage is per-tab, IndexedDB is async transactional object store for MBs of structured data.
Q7. What is the DOM? Is HTML = DOM?
HTML is a text serialization. The DOM is the in-memory tree the browser builds from it and the JS API to manipulate it. JS mutations update the DOM, not the original HTML string.
Q8. How does the browser render a page? (Critical Rendering Path)
Bytes → chars → tokens → DOM. CSS bytes → CSSOM. DOM + CSSOM → Render Tree → Layout → Paint → Composite. Scripts can block parsing; CSS blocks rendering.
Q9. What does rel="noopener noreferrer" do?
Prevents the opened tab from controlling the opener via window.opener (tabnabbing) and strips the Referer header. Essential for external target="_blank".
Q10. Difference between <section>, <article>, <div>?
<div> = no meaning. <section> = thematic group with heading. <article> = self-contained, syndicatable.
Q11. How do you make images responsive?
Use srcset+sizes for resolution switching, <picture> + <source type> for format/art-direction switching, set intrinsic width/height for CLS, and serve AVIF/WebP with JPEG fallback.
Q12. What is the accessibility tree?
A parallel tree derived from the DOM + ARIA that exposes roles, names, and states to assistive tech. display: none and aria-hidden remove nodes from it.
Q13. What is a Web Component?
A standardized way to build reusable elements with three specs: Custom Elements (customElements.define), Shadow DOM (encapsulated DOM/CSS), and HTML Templates (<template>/<slot>).
Q14. How do iframes communicate with parents safely?
postMessage with targetOrigin specified, and always validate event.origin on the receiving side. Use sandbox to restrict iframe capabilities.
Q15. How does <template> differ from just hidden HTML?
A <template>'s contents are parsed into a separate inert DocumentFragment. Scripts don't run, images don't load, and it isn't rendered. You clone it with content.cloneNode(true).
Q16. Progressive Enhancement vs Graceful Degradation?
PE = build the simplest version first (HTML that works everywhere), then layer CSS and JS. GD = build the full version, then add fallbacks for older browsers. PE is preferred for accessibility and resilience.
Q17. SEO quick wins in HTML?
Meaningful <title>, concise meta description, unique H1, semantic landmarks, canonical URL, OG tags, structured data (JSON-LD), proper hreflang for i18n, valid sitemap.
Q18. What is Subresource Integrity (SRI)?
An integrity attribute (SHA hash) on <script> or <link> that makes the browser reject the resource if its contents have been tampered with. Essential when loading from third-party CDNs.
Q19. Why is <button> better than <div onclick>?
Buttons are focusable, keyboard operable (Enter/Space), announced by AT with role "button", and submit forms by default. A div requires role, tabindex, and key handlers and still is more fragile.
Q20. What's the difference between disabled and readonly?
disabled makes the input not focusable, not submitted with the form, and visually grayed. readonly keeps it focusable and submitted but not editable.
Q21. When would you use <picture> over srcset?
Use srcset/sizes when variants are different sizes of the same image. Use <picture> when you need art direction (different crops for mobile/desktop) or format fallbacks (AVIF → WebP → JPEG).
Q22. What is the preload scanner?
A secondary lightweight HTML parser that scans the byte stream ahead of the main parser to discover and fetch resources (CSS, JS, images) in parallel. Resources injected via JS miss it — that's why document.writed scripts are slow.
Q23. How do you implement a modal accessibly in pure HTML?
Use the native <dialog> with .showModal() — it traps focus, adds a backdrop, supports ESC to close. For custom modals: role="dialog" aria-modal="true", manage focus manually, trap Tab, restore focus on close.
Q24. HTML injection vs XSS?
HTML injection inserts markup without scripts (defacement). XSS inserts executable JS (session theft, CSRF, data theft). Both are prevented by escaping user content and using CSP.
Q25. What's new in HTML5 vs HTML4?
Semantic tags (header/nav/main/article/section/aside/footer), multimedia (audio/video/canvas), form types & validation, APIs (Geolocation, Storage, WebSockets, Workers), Web Components, <dialog>, <details>, microdata/ARIA.

30. Rapid-Fire Gotchas & One-Liners Advanced

  • Self-closing /> in HTML5 is ignored — <br/> and <br> are identical.
  • <p> cannot contain block elements — inserting a <div> auto-closes the <p>.
  • <a> can wrap block-level content (HTML5 change).
  • <button> inside a <form> defaults to type=submit.
  • disabled="false" is still disabled. Boolean attributes ignore value.
  • <label for> must match id, not name.
  • autofocus should appear only once per page.
  • Radio buttons only group if they share name.
  • Checkbox is NOT submitted if unchecked — use a hidden input with same name as fallback.
  • input[type=file] cannot be styled directly — hide + label trick.
  • contenteditable elements don't fire change; listen to input.
  • dialog.show() vs dialog.showModal() — only the modal one traps focus & adds backdrop.
  • srcset uses w (width) descriptors with sizes, or x (density) without.
  • Never put interactive elements inside <button> or <a> (nested button → invalid).
  • aria-hidden="true" on a focusable element creates an "invisible trap" for screen readers.
  • Inline SVG is accessible; background-image SVG is not.
  • loading="lazy" on the LCP image hurts LCP.
  • meta refresh for redirects hurts a11y and SEO — use HTTP 301.
  • tabindex="-1" makes an element focusable via script only (not Tab key).
  • <picture> does NOT affect layout — the inner <img> is what renders.
  • HTML entities you should know: &amp;, &lt;, &gt;, &quot;, &#39;, &nbsp;.
  • Comments <!-- ... --> are shipped to the client — never put secrets in them.
