1. Interview Q&A: DOM Tree & Selectors

🎯 DOM Tree Questions

Easy What is the DOM?

Answer: The DOM (Document Object Model) is a tree-structured representation of an HTML document created by the browser. It's an API that lets JavaScript read and modify the page content, structure, and styles. The DOM is NOT the HTML source — it's what the browser builds after parsing HTML (includes elements added by JS, fixes invalid markup, etc.).

Easy What are the different node types in the DOM?

Answer: Main node types: Element (type 1) — HTML tags. Text (type 3) — text content between tags (including whitespace!). Comment (type 8) — HTML comments. Document (type 9) — the root. DocumentFragment (type 11) — lightweight container. Attribute (type 2, deprecated — use getAttribute). Check with node.nodeType or node instanceof Element.

Easy How do you traverse the DOM tree?

Answer: Parent: node.parentElement, node.parentNode. Children: node.children (elements only), node.childNodes (all nodes incl. text). Siblings: node.nextElementSibling, node.previousElementSibling. First/Last: node.firstElementChild, node.lastElementChild. Use Element variants to skip whitespace text nodes.

Medium What's the difference between querySelector and getElementById? Which is faster?

Answer: getElementById only selects by ID and returns a single element — it's the fastest DOM query because IDs are stored in a hash map (O(1) lookup). querySelector accepts any CSS selector (classes, attributes, pseudo-selectors) but is slightly slower because it traverses the tree. For IDs, use getElementById. For everything else, querySelector/querySelectorAll.

Medium Difference between NodeList and HTMLCollection?

Answer: HTMLCollection (from getElementsBy*) is LIVE — automatically updates when DOM changes. NodeList from querySelectorAll is STATIC (snapshot). NodeList has forEach(); HTMLCollection doesn't (convert with Array.from()). NodeList can contain any node type; HTMLCollection only contains elements.

Medium What's the difference between parentNode and parentElement?

Answer: parentElement returns the parent only if it's an Element node. parentNode returns any parent node (including Document). Difference matters only at the top: document.documentElement.parentNode → #document; document.documentElement.parentElement → null (because Document isn't an Element). In practice they're interchangeable 99% of the time.

Medium What is the difference between children and childNodes?

Answer: children returns an HTMLCollection of Element children ONLY (skips text, comments). childNodes returns a NodeList of ALL child nodes (including whitespace text nodes and comments). Always use children unless you specifically need text/comment nodes. Common bug: childNodes.length > expected because of whitespace text nodes between tags.

Hard What is the difference between document.querySelector('.item') and document.getElementsByClassName('item')[0]?

Answer: Functionally similar but: (1) querySelector returns null if not found; getElementsByClassName returns an empty live collection. (2) querySelector takes a snapshot; getElementsByClassName returns a LIVE reference that auto-updates. (3) querySelector is marginally slower (CSS selector parsing). (4) querySelector can use complex selectors (.item:not(.hidden)); getElementsByClassName cannot.

Hard How does the DOM differ from the HTML source code?

Answer: Multiple differences: (1) Browser error-correction: missing <html>/<body>/<head> are auto-added, unclosed tags closed, invalid nesting fixed. (2) <table> without <tbody> gets one auto-inserted. (3) JS modifications: innerHTML changes, createElement + appendChild. (4) <template> content isn't in main DOM. (5) Shadow DOM isn't in light DOM. View-source shows original HTML; DevTools shows live DOM.

Hard Explain the concept of "live" vs "static" collections with a bug example.

Answer: Live HTMLCollection from getElementsByClassName auto-updates when DOM changes. Bug: iterating forward while removing elements — the collection shrinks mid-loop, skipping every other element. Example: collection has [A, B, C, D], remove A → collection becomes [B, C, D], index moves to 1 → skips B. Fix: iterate backwards, or convert to array first with [...collection] or Array.from().

Expert What is the difference between document and window in terms of the DOM?

Answer: window is the global object (represents the browser window/tab) — contains setTimeout, fetch, location, history, navigator, and the document. document is the DOM entry point (represents the loaded HTML page) — contains querySelector, createElement, body, head. window.document === document. In a frame: window is the frame's window, document is the frame's document. In Web Workers: there is no window or document (self is the global).

Expert How does the browser handle duplicate IDs in the DOM?

Answer: HTML spec says IDs must be unique, but browsers DON'T throw errors for duplicates. getElementById returns the FIRST element with that ID. querySelectorAll("#myId") returns ALL matching elements. CSS #myId styles ALL elements with that ID. This causes bugs in: label[for], anchor links, aria-labelledby/describedby. Duplicate IDs are a common source of subtle accessibility bugs.

2. Interview Q&A: DOM Manipulation

🎯 DOM Manipulation Questions

Medium innerHTML vs textContent vs innerText — when to use each?

Answer: textContent: sets/gets raw text, fastest, escapes HTML (XSS-safe), includes hidden elements' text. innerText: gets "visible" text only (triggers reflow to check visibility!), slower. innerHTML: parses/renders HTML — powerful but XSS risk with user input. Rule: use textContent for text, innerHTML only for trusted HTML, never innerText in hot paths.

Hard How do you efficiently add 10,000 elements to the DOM?

Answer: Three techniques: (1) DocumentFragment — build all elements off-DOM in a fragment, then appendChild once (single reflow). (2) Build HTML string, set innerHTML once (faster than createElement loop). (3) Clone a template node. NEVER append elements one by one in a loop — each triggers a reflow. For truly massive lists, use virtual scrolling (only render visible items).

// Method 1: DocumentFragment
const frag = document.createDocumentFragment();
for (let i = 0; i < 10000; i++) {
  const div = document.createElement("div");
  div.textContent = `Item ${i}`;
  frag.appendChild(div);
}
container.appendChild(frag); // 1 reflow

// Method 2: innerHTML batch (faster for simple markup)
let html = "";
for (let i = 0; i < 10000; i++) {
  html += `<div>Item ${i}</div>`;
}
container.innerHTML = html; // 1 parse + 1 reflow

Expert Explain insertAdjacentHTML — why is it better than innerHTML for partial updates?

Answer: innerHTML replaces ALL children — the browser must serialize existing content, parse new HTML, and rebuild the entire subtree (destroying event listeners, losing state). insertAdjacentHTML inserts NEW HTML at a specific position without touching existing DOM nodes. Events, references, and state of existing elements are preserved. Positions: beforebegin, afterbegin, beforeend, afterend.

Easy How do you create and add elements to the DOM?

Answer: Use document.createElement("tag") to create an element. Set properties (textContent, className, id, dataset). Then insert with: parent.appendChild(element), parent.insertBefore(new, reference), parent.append(elements...), or element.before()/after()/replaceWith(). Append creates the element in memory first (no reflow until inserted).

Easy What's the difference between remove() and removeChild()?

Answer: element.remove() removes itself from the DOM (modern, clean). parent.removeChild(child) removes a child from its parent and returns the removed node. removeChild requires a reference to the parent. Both keep the element in memory (can re-insert later). The element reference remains valid — only detached from the DOM tree.

Medium What is a DocumentFragment and why use it?

Answer: DocumentFragment is a lightweight, "virtual" DOM node that exists only in memory (not part of the live DOM tree). You can append multiple children to it without triggering any reflows. When you insert the fragment into the DOM, only the fragment's CHILDREN are inserted (the fragment itself disappears). Result: only ONE reflow for multiple insertions.

Medium Difference between append() and appendChild()?

Answer: appendChild: accepts only Node objects, returns the appended node, can only add one node at a time. append: accepts Nodes AND strings (auto-creates text nodes), returns undefined, can add multiple arguments at once. append is newer and more flexible. Also: prepend(), before(), after(), replaceWith() — same modern API family.

Medium How does cloneNode work and what's the deep clone gotcha?

Answer: element.cloneNode(false) clones the element only (no children). element.cloneNode(true) clones the element AND all descendants (deep clone). Gotchas: (1) Event listeners are NOT cloned. (2) IDs are copied — duplicates in DOM! (3) form input values ARE copied. (4) Canvas content is NOT copied. Always fix IDs after cloning. Re-attach event listeners via delegation on a parent.

Hard What is the XSS risk with innerHTML and how do you prevent it?

Answer: If user input is put into innerHTML, an attacker can inject <script> tags, event handlers (onerror, onload), or <img src=x onerror="steal()">. Prevention: (1) Use textContent for user data (auto-escapes HTML). (2) Use DOMPurify library to sanitize HTML. (3) CSP headers (Content-Security-Policy). (4) Angular/React auto-escape by default (Angular: [innerHTML] with DomSanitizer). Never concatenate user input into innerHTML.

Hard What's the difference between setAttribute and direct property assignment?

Answer: Properties reflect attributes but aren't identical. element.id = "x" and element.setAttribute("id", "x") are equivalent for standard attributes. But: (1) Properties can have types (checked is boolean; getAttribute("checked") returns string or null). (2) Custom attributes need setAttribute (properties don't auto-create attributes). (3) Some names differ: class (attr) vs className (prop), for (attr) vs htmlFor (prop). (4) data-* uses dataset property.

Expert Explain the difference between reflow, repaint, and composite. What triggers each?

Answer: Reflow (Layout): recalculates geometry (position, size) — triggered by width/height/margin/padding changes, DOM insertion, reading offsetWidth. Repaint: redraws pixels — triggered by color/background/shadow changes (no geometry shift). Composite: GPU combines layers — triggered by transform/opacity changes. Cost: Reflow > Repaint > Composite. transform/opacity are cheapest because they skip Layout and Paint entirely (GPU-only).

3. Interview Q&A: Custom Events & EventEmitter

🎯 Custom Events Questions

Easy What is event delegation and why use it?

Answer: Event delegation attaches ONE listener to a parent element instead of individual listeners on each child. It works because events bubble up the DOM. When clicked, check event.target or event.target.closest(selector) to identify which child was clicked. Benefits: (1) Works for dynamically added elements. (2) Less memory (1 listener vs 1000). (3) Less setup code. Used by jQuery, React synthetic events, Angular's event binding internally.

Easy What's the difference between event.target and event.currentTarget?

Answer: event.target: the element that TRIGGERED the event (what was actually clicked). event.currentTarget: the element the listener is ATTACHED to. With delegation: listener on <ul>, click on <li> → target is li, currentTarget is ul. In arrow functions inside class methods, this === the instance (not the element), so use event.currentTarget instead.

Medium Explain event capturing vs bubbling. When would you use capturing?

Answer: Events go through 3 phases: (1) Capturing: window → document → ... → parent (top-down). (2) Target: event reaches the target element. (3) Bubbling: target → parent → ... → document → window (bottom-up). Use capturing (addEventListener's 3rd arg: true) when: you need to intercept BEFORE the target handles it (e.g., global click tracking, focus management). Most use cases need bubbling (default).

Medium What's the difference between stopPropagation and stopImmediatePropagation?

Answer: stopPropagation: stops event from moving to the next element in the chain (no more capturing/bubbling), but OTHER listeners on the SAME element still fire. stopImmediatePropagation: stops propagation AND prevents other listeners on the SAME element from firing. Use stopImmediate when you want a handler to be the absolute last one to run.

Medium How do you communicate between unrelated components without a framework?

Answer: (1) Custom Events on a shared DOM element (document): dispatch CustomEvent with detail data, any component can listen. (2) Event Emitter (pub/sub) pattern: a singleton bus with on/emit/off methods. (3) BroadcastChannel for cross-tab. (4) Window postMessage for cross-origin. Angular uses services with RxJS Subjects for the same purpose.

Medium What's the difference between CustomEvent and Event?

Answer: CustomEvent extends Event and adds a detail property for passing custom data. With plain new Event("myevent"), you can't attach payload data. With new CustomEvent("myevent", { detail: { id: 1, name: "test" } }), listeners access data via e.detail. Both support bubbles/cancelable/composed options.

Hard Explain event.preventDefault() — which events are cancelable?

Answer: preventDefault() stops the browser's default behavior (form submit, link navigation, text selection). Only events with cancelable: true can be prevented. Non-cancelable examples: scroll, focus, blur (but focusin IS cancelable!). Check with event.cancelable before calling. If you preventDefault on wheel/touchmove, scrolling stops (use passive: true to tell browser you won't prevent, improving scroll performance).

Hard What are passive event listeners and why do they matter?

Answer: { passive: true } tells the browser "this listener will NOT call preventDefault()". This lets the browser start scrolling/painting IMMEDIATELY without waiting for your JS to execute. Without it, touch/wheel events block scrolling until the handler completes (causing jank). Chrome makes touchstart/touchmove passive by default on document/window. Use passive for scroll/touch handlers that don't need to prevent defaults.

Hard Implement a type-safe EventEmitter with once() and wildcard support.

class EventBus {
  #events = new Map();

  on(event, fn) {
    if (!this.#events.has(event)) this.#events.set(event, new Set());
    this.#events.get(event).add(fn);
    return () => this.off(event, fn); // Return unsubscribe function
  }

  once(event, fn) {
    const wrapper = (...args) => { fn(...args); this.off(event, wrapper); };
    wrapper._original = fn; // For off() to find it
    return this.on(event, wrapper);
  }

  off(event, fn) {
    const set = this.#events.get(event);
    if (!set) return;
    // Check for once() wrappers
    for (const handler of set) {
      if (handler === fn || handler._original === fn) {
        set.delete(handler);
        break;
      }
    }
  }

  emit(event, ...args) {
    // Exact match
    this.#events.get(event)?.forEach(fn => fn(...args));
    // Wildcard listeners
    this.#events.get("*")?.forEach(fn => fn(event, ...args));
  }

  clear() { this.#events.clear(); }
}

Expert What's the difference between composed: true and bubbles: true in events? When do you need both?

Answer: bubbles: true makes the event propagate up the DOM tree (child → parent → ... → document). composed: true makes the event cross Shadow DOM boundaries. Without composed: true, an event dispatched inside Shadow DOM stays trapped there — the host element's listeners won't see it. You need BOTH for Web Component events that should be observable by parents: new CustomEvent("x", { bubbles: true, composed: true }).

Expert How would you implement debounce and throttle for DOM events from scratch?

Answer: Debounce: delays execution until N ms after the LAST call (good for search input). Throttle: executes at most once per N ms (good for scroll/resize). Key difference: debounce waits for inactivity; throttle limits rate. Debounce implementation: clearTimeout on each call, set new timeout. Throttle: check if enough time elapsed since last execution, or use requestAnimationFrame for visual changes.

// Debounce
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// Throttle (leading edge)
function throttle(fn, limit) {
  let lastCall = 0;
  return (...args) => {
    const now = Date.now();
    if (now - lastCall >= limit) {
      lastCall = now;
      fn(...args);
    }
  };
}

// Usage:
input.addEventListener("input", debounce(search, 300));
window.addEventListener("scroll", throttle(updateNav, 100));

Hard How do you properly clean up event listeners to prevent memory leaks?

Answer: (1) Always store a reference to the handler function — anonymous functions can't be removed. (2) Use removeEventListener with the EXACT same function reference. (3) Use { once: true } for one-shot listeners (auto-removes). (4) Use AbortController signal — abort() removes ALL listeners attached with that signal at once. (5) In SPAs, clean up on route change/component destroy. (6) WeakRef for observer patterns (auto GC when target is gone).

// AbortController pattern (cleanest for bulk removal):
const controller = new AbortController();
element.addEventListener("click", handler, { signal: controller.signal });
element.addEventListener("keydown", handler2, { signal: controller.signal });
window.addEventListener("resize", handler3, { signal: controller.signal });

// Remove ALL at once:
controller.abort(); // All three listeners removed!

4. Interview Q&A: Forms & Validation

🎯 Form Questions

Easy What's the difference between the 'input' and 'change' events?

Answer: 'input' fires on EVERY change (keystroke, paste, autofill) — real-time. 'change' fires only when the element LOSES FOCUS (blur) and the value has changed since gaining focus. Use 'input' for live search/validation. Use 'change' for final-value operations (like form save on blur). For checkboxes/radios/selects, 'change' fires immediately on selection.

Medium How does FormData work and why is it useful?

Answer: FormData collects all form control values into key-value pairs automatically (respects name attributes, handles files, skips disabled inputs). Advantages: (1) No manual value collection from each input. (2) Handles file uploads natively (multipart/form-data). (3) Works with fetch() body directly. (4) Object.fromEntries(formData) gives a plain object. Angular's Reactive Forms do similar things with FormGroup.value.

Hard How would you implement custom form validation without a framework?

// Use the Constraint Validation API
function validateForm(form) {
  const errors = {};

  const email = form.querySelector("[name='email']");
  if (email.validity.valueMissing) errors.email = "Email is required";
  else if (email.validity.typeMismatch) errors.email = "Invalid email format";

  const password = form.querySelector("[name='password']");
  if (password.value.length < 8) {
    password.setCustomValidity("Password must be 8+ characters");
    errors.password = "Password must be 8+ characters";
  } else {
    password.setCustomValidity(""); // Clear custom error
  }

  // Show errors
  Object.entries(errors).forEach(([field, msg]) => {
    form.querySelector(`[name='${field}'] + .error`).textContent = msg;
  });

  return Object.keys(errors).length === 0;
}

form.addEventListener("submit", (e) => {
  e.preventDefault();
  if (validateForm(form)) {
    // Submit
  }
});

// Real-time validation on input
form.querySelectorAll("input").forEach(input => {
  input.addEventListener("input", () => {
    input.setCustomValidity("");
    if (input.checkValidity()) {
      input.classList.remove("invalid");
    }
  });
  input.addEventListener("invalid", (e) => {
    e.preventDefault(); // Suppress browser tooltip
    input.classList.add("invalid");
  });
});

Easy How do you prevent a form from submitting and refreshing the page?

Answer: Call event.preventDefault() in the submit event handler: form.addEventListener("submit", (e) => { e.preventDefault(); // handle with JS }). This stops the browser's default form submission behavior (which causes a full page reload). All modern SPAs (Angular, React) do this — forms are handled via fetch/HttpClient instead.

Medium What is the Constraint Validation API?

Answer: A built-in browser API for form validation without libraries. Key methods: element.checkValidity() (returns boolean), element.reportValidity() (shows browser tooltip), element.setCustomValidity("msg") (set custom error). Key properties: element.validity (ValidityState object with flags: valueMissing, typeMismatch, tooShort, patternMismatch, etc.). Works with required, type, min, max, pattern attributes.

Hard How do you handle file uploads with preview before sending?

Answer: Use FileReader or URL.createObjectURL to preview: (1) Listen to input's 'change' event, get files from input.files. (2) For image preview: URL.createObjectURL(file) gives a blob URL for img.src (faster, auto-released) or FileReader.readAsDataURL(file) gives base64 string. (3) Validate file.type, file.size before upload. (4) Use FormData with fetch for multipart upload. (5) Revoke object URLs with URL.revokeObjectURL() to prevent memory leaks.

Expert How would you implement real-time collaborative form editing?

Answer: (1) WebSocket connection to sync state. (2) On each 'input' event, debounce and send { field, value, cursor position } to server. (3) Server broadcasts to other clients. (4) Other clients update field values without triggering their own 'input' events (use element.value = x directly, or flag to ignore). (5) Handle conflicts with Operational Transform or CRDT. (6) Show other users' cursors/selections with custom highlights. Angular apps use RxJS webSocket subject for this.

5. Interview Q&A: Observers

🎯 Observer Questions

Medium How would you implement lazy loading images without a library?

Answer: Use IntersectionObserver to watch images with data-src. When they enter the viewport (isIntersecting = true), set img.src = img.dataset.src and unobserve. Use rootMargin (e.g., "200px") to start loading before the image is visible. Modern approach: just use loading="lazy" attribute (native, no JS needed), but IntersectionObserver gives more control.

// Native (simplest): <img src="photo.jpg" loading="lazy">

// IntersectionObserver (full control):
const io = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;
      img.removeAttribute("data-src");
      io.unobserve(img);
    }
  });
}, { rootMargin: "200px" }); // Start 200px before viewport

document.querySelectorAll("img[data-src]").forEach(img => io.observe(img));

Hard How would you implement infinite scroll?

Answer: Place a sentinel element at the bottom of the list. Use IntersectionObserver to watch it. When visible → fetch next page, append items, re-position sentinel. Add a loading state to prevent duplicate fetches. Better than scroll events because: no throttling needed, more performant, works in nested scrollable containers.

Medium What's the difference between IntersectionObserver, MutationObserver, and ResizeObserver?

Answer: IntersectionObserver: watches elements entering/leaving viewport (or a scroll container) — lazy load, animations, infinite scroll. MutationObserver: watches DOM changes (child added/removed, attributes changed, text modified). ResizeObserver: watches elements being resized (responsive components, chart resizing). All three are async and non-blocking (batch callbacks in microtask-like timing).

Easy What is IntersectionObserver used for?

Answer: IntersectionObserver watches when elements enter or leave the viewport (or any scrollable container). Common uses: lazy loading images, infinite scroll, triggering animations on scroll, ad impression tracking, sticky header changes. Advantages over scroll event listeners: no manual throttling needed, works in nested containers, battery-efficient (browser-optimized).

Medium How does MutationObserver work and when would you use it?

Answer: MutationObserver watches for DOM changes: childList (elements added/removed), attributes (class/style changes), characterData (text content changes), subtree (deep watch). Callback receives MutationRecord[] with type, target, addedNodes, removedNodes, etc. Use cases: third-party widget integration (detect changes), auto-TOC generation, accessibility widgets, polyfills that need to detect new elements.

Hard What are the performance implications of MutationObserver?

Answer: MutationObserver batches mutations and delivers them asynchronously (microtask timing), unlike the deprecated synchronous Mutation Events (which fired on every single change). But: (1) Observing subtree: true on document.body captures EVERYTHING — expensive callback processing. (2) Large DOM changes (innerHTML on big tree) produce massive mutation lists. (3) Callbacks that modify DOM can trigger cascading observations. Best practice: observe specific elements, not the entire document. Disconnect when done.

Expert How would you build a container query polyfill using ResizeObserver?

Answer: ResizeObserver watches container size changes. When the container crosses a breakpoint threshold, toggle CSS classes on it (e.g., .container--compact, .container--wide). Child elements style themselves based on parent's class (proxy for container queries). This is exactly what CSS Container Queries now do natively (@container), but ResizeObserver gives the same power in JS with full browser support.

// ResizeObserver — watch when elements change size
// Better than window.resize because it observes SPECIFIC elements
// Works for: responsive components, auto-sizing textareas, chart libraries

const resizeObserver = new ResizeObserver((entries) => {
  for (const entry of entries) {
    const { width, height } = entry.contentRect;
    console.log(`Element resized: ${width}x${height}`);

    // Example: switch component layout based on container width
    if (width < 400) {
      entry.target.classList.add("compact");
      entry.target.classList.remove("wide");
    } else {
      entry.target.classList.add("wide");
      entry.target.classList.remove("compact");
    }
  }
});

6. Interview Q&A: Storage & Cookies

🎯 Storage Questions

Easy What is localStorage and how do you use it?

Answer: localStorage is a synchronous key-value storage API (string→string) that persists across sessions. Methods: setItem(key, value), getItem(key), removeItem(key), clear(). Stores ~5-10MB per origin. Data survives browser close. Gotcha: stores strings only — JSON.stringify() for objects, JSON.parse() on retrieval. Blocking (synchronous) — don't use in performance-critical paths.

Medium localStorage vs sessionStorage vs cookies — when to use each?

Answer: localStorage: persistent data that shouldn't expire (user preferences, theme). sessionStorage: data for a single tab session (form draft, unsaved state) — cleared on tab close. Cookies: data that MUST be sent to server with every request (auth tokens, session IDs) — only 4KB but have HttpOnly/Secure/SameSite for security. For large data, use IndexedDB.

Medium How does the 'storage' event enable cross-tab communication?

Answer: When localStorage changes in one tab, the 'storage' event fires in ALL OTHER same-origin tabs (not the one that made the change). This enables sync: logout in one tab → all tabs detect the change and redirect. Event provides: key, oldValue, newValue, url. Only works with localStorage (not sessionStorage).

Medium What are cookie attributes and their security implications?

Answer: HttpOnly: JS can't access (prevents XSS token theft). Secure: only sent over HTTPS. SameSite=Strict: never sent cross-site (prevents CSRF). SameSite=Lax: sent on top-level navigations only (default in modern browsers). Domain/Path: scope the cookie to specific subdomains/paths. Expires/Max-Age: when the cookie dies. Best practice: auth cookies should be HttpOnly + Secure + SameSite=Strict.

Hard How do you handle localStorage in SSR (server-side rendering)?

Answer: localStorage doesn't exist on the server (no window/document). Solutions: (1) Guard with typeof window !== 'undefined'. (2) Use Angular's isPlatformBrowser(platformId). (3) Create an abstract StorageService that returns no-op on server. (4) Use transfer state (TransferState in Angular) to pass initial values from server to client without localStorage.

Hard What are the security implications of storing auth tokens in localStorage?

Answer: localStorage is accessible by ANY JS on the same origin — if an XSS attack injects script, they can read all tokens. Cookies with HttpOnly flag are NOT accessible via JS (document.cookie can't see them) — safer for auth tokens. Best practice: store refresh tokens in HttpOnly Secure cookies (server-side), store short-lived access tokens in memory (JS variable). Never store sensitive data in localStorage.

Hard When would you use IndexedDB over localStorage?

Answer: IndexedDB when: (1) Storing >5MB data (IndexedDB allows hundreds of MB). (2) Storing complex objects (no serialization needed — stores JS objects directly). (3) Need indexes for querying/searching. (4) Need transactions (atomic multi-operation writes). (5) Binary data (Blob, ArrayBuffer). (6) Offline-first apps (Service Worker + IndexedDB). localStorage is simpler for small key-value data (<5MB strings).

Expert Explain the Storage Quota API and how browsers manage storage limits.

Answer: navigator.storage.estimate() returns { quota, usage } in bytes. Browsers typically allow 50-80% of disk per origin. 7. Interview Q&A: Fetch & Network

🎯 Fetch Questions

Easy What is the Fetch API and how does it differ from XMLHttpRequest?

Answer: Fetch is a modern Promise-based API for network requests. Differences from XHR: (1) Returns Promises (no callback hell). (2) Cleaner API (Request/Response objects). (3) Supports streaming (response.body is a ReadableStream). (4) Better CORS handling. (5) No upload progress (XHR has it). (6) Doesn't reject on HTTP errors (only network failures). (7) Can't abort without AbortController (XHR has abort()). (8) No built-in timeout.

Easy Why does fetch not reject on 404 or 500 errors?

Answer: fetch only rejects on NETWORK failures (no internet, DNS failure, CORS blocked). HTTP errors (400, 404, 500) are valid responses from the server — the request succeeded in reaching the server and getting a response. You must check response.ok (true for 200-299) or response.status manually. This is a common bug when migrating from axios (which throws on HTTP errors).

Medium How do you cancel a fetch request?

Answer: Use AbortController: create controller, pass controller.signal to fetch options, call controller.abort() to cancel. Fetch rejects with AbortError (catch it: if (err.name === "AbortError")). Use cases: cancel on component unmount, cancel previous request on new search input, timeout implementation. AbortSignal.timeout(5000) creates a signal that auto-aborts after 5s.

Medium How do you handle file uploads with progress tracking?

// fetch doesn't natively support upload progress
// Use XMLHttpRequest for upload progress:
function uploadWithProgress(file, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    const formData = new FormData();
    formData.append("file", file);

    xhr.upload.addEventListener("progress", (e) => {
      if (e.lengthComputable) {
        onProgress(Math.round((e.loaded / e.total) * 100));
      }
    });

    xhr.addEventListener("load", () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(JSON.parse(xhr.responseText));
      } else {
        reject(new Error(`HTTP ${xhr.status}`));
      }
    });

    xhr.addEventListener("error", () => reject(new Error("Network error")));
    xhr.open("POST", "/api/upload");
    xhr.send(formData);
  });
}

async function downloadWithProgress(url) {

Hard Explain CORS. Why does it exist and how do you fix CORS errors?

Answer: CORS (Cross-Origin Resource Sharing) is a browser security mechanism that blocks JS from reading responses from a different origin (protocol + domain + port). It exists to prevent malicious sites from reading data from your APIs using your cookies. The SERVER must send Access-Control-Allow-Origin headers to permit cross-origin access. "Preflight" OPTIONS requests happen for non-simple requests (custom headers, PUT/DELETE). Fixes: server adds CORS headers, or use a proxy (Angular: proxy.conf.json in dev).

Expert What's the difference between CORS and CSP?

Answer: CORS controls which origins can READ your server's responses (server-side protection, configured via response headers). CSP (Content Security Policy) controls what resources YOUR page can load/execute (client-side protection, configured via response headers too). CORS answers: "Who can call my API?" CSP answers: "What can run on my page?" CSP prevents inline scripts, unauthorized sources — blocks XSS. CORS prevents data theft from other origins.

Medium What's the difference between fetch credentials options: 'same-origin', 'include', 'omit'?

Answer: credentials: "omit" — never send cookies/auth headers (default for cross-origin). credentials: "same-origin" — send cookies only to same origin (default for same-origin). credentials: "include" — always send cookies even cross-origin (requires server CORS header: Access-Control-Allow-Credentials: true AND specific origin, not wildcard *). Angular HttpClient sends cookies for same-origin by default; use withCredentials: true for cross-origin.

Hard How do you implement request timeout, retry, and caching in a fetch wrapper?

Answer: Timeout: AbortSignal.timeout(ms) or race fetch against a timer. Retry: catch errors, loop with exponential backoff (wait 1s, 2s, 4s), skip retry on 4xx (client errors). Cache: Map with URL as key, store { data, timestamp }, check TTL before returning cached data. Also deduplicate: if same request is in-flight, return the same Promise. Production: use libraries like ky, axios, or Angular's HttpInterceptor chain.

Expert Explain Streaming with fetch — ReadableStream and NDJSON.

Answer: response.body is a ReadableStream. You can read it chunk-by-chunk without waiting for the full response (useful for SSE alternatives, large downloads, AI streaming). Use response.body.getReader(), loop with reader.read() until done. NDJSON (Newline-Delimited JSON): server sends one JSON object per line — client parses each line as it arrives. This is how ChatGPT streaming works. TextDecoderStream converts bytes to text for line-by-line processing.

Expert What is a Service Worker and how does it intercept fetch requests?

Answer: A Service Worker is a background script (separate thread, no DOM access) that acts as a programmable network proxy. It intercepts ALL fetch requests from its scope via the 'fetch' event. It can: serve from cache (offline support), modify requests/responses, implement custom caching strategies (cache-first, network-first, stale-while-revalidate). Lifecycle: install → activate → idle (with fetch/message events). Registered with navigator.serviceWorker.register().

// ─── Sortable List (drag to reorder) ─────────────────────

function makeSortable(container) {
  let draggedItem = null;

  container.addEventListener("dragstart", (e) => {
    draggedItem = e.target.closest("li");
    draggedItem.classList.add("dragging");
  });

  container.addEventListener("dragend", () => {
    draggedItem.classList.remove("dragging");
    draggedItem = null;
  });

  container.addEventListener("dragover", (e) => {
    e.preventDefault();
    const afterElement = getDragAfterElement(container, e.clientY);
    if (afterElement) {
      container.insertBefore(draggedItem, afterElement);
    } else {
      container.appendChild(draggedItem);
    }
  });

  function getDragAfterElement(container, y) {
    const items = [...container.querySelectorAll("li:not(.dragging)")];
    return items.reduce((closest, child) => {
      const box = child.getBoundingClientRect();
      const offset = y - box.top - box.height / 2;
      if (offset < 0 && offset > closest.offset) {
        return { offset, element: child };
      }
      return closest;
    }, { offset: Number.NEGATIVE_INFINITY }).element;
  }
}

11. DOM Interview Rapid Fire — Output Prediction & Gotchas

🎯 Rapid Fire Questions (Often Asked in Interviews)

Easy What does document.querySelectorAll("div") return if there are no divs?

Answer: An empty NodeList (NOT null). Length is 0. forEach loop runs 0 times. Always safe to iterate — no null check needed. This is different from querySelector which returns null when no match.

Easy What's the difference between window.onload and document.addEventListener("DOMContentLoaded")?

Answer: window.onload waits for ALL resources (images, CSS, frames). DOMContentLoaded fires when HTML is parsed (DOM ready, images may still be loading). Also: onload is a single handler (overwritten by re-assignment); addEventListener can stack multiple handlers. For modern code, always use addEventListener("DOMContentLoaded") or defer scripts.

Medium What happens when you set element.style.display = "none" and then read element.offsetHeight?

Answer: Returns 0. Elements with display:none have no box in the layout tree — no dimensions, no position. This is different from visibility:hidden (still has dimensions, offsetHeight returns actual height) and opacity:0 (same as visibility — takes space). Trick: to measure a hidden element, temporarily show it off-screen (position:absolute, left:-9999px).

Medium What's the output of: document.body.children[0] vs document.body.childNodes[0]?

Answer: children[0] returns the first Element child (skips whitespace text nodes). childNodes[0] returns the first Node — which is often a whitespace Text node (the newline/indentation between <body> and the first element). This is why childNodes is surprising — HTML whitespace creates text nodes.

Medium Can you explain getBoundingClientRect() and when to use it?

Answer: Returns a DOMRect with: top, right, bottom, left (relative to viewport), width, height. Use for: tooltip positioning, collision detection, checking if element is in viewport (before IntersectionObserver), calculating scroll distances. Gotcha: returns fractional pixels. Triggers a forced layout if styles are dirty (reading geometry = forced synchronous layout).

Medium What happens to event listeners when you remove an element from the DOM?

Answer: Listeners remain on the element object in memory. If you have a reference to the element, you can re-insert it and listeners still work. If no references exist, the element is garbage collected (listeners freed automatically). BUT: if a listener references a closure that references the element → circular reference (modern engines handle this, but it's a code smell). Best practice: removeEventListener before remove() for clarity.

Hard Explain the "Virtual DOM" concept — how does it differ from the real DOM?

Answer: Virtual DOM (React's approach) is a lightweight JS object tree mirroring the real DOM. On state change: (1) New virtual tree created. (2) Diff against previous virtual tree. (3) Minimal patches applied to real DOM. Benefits: batched updates, less direct DOM manipulation. Angular does NOT use virtual DOM — it uses change detection + direct DOM updates via Renderer2. Svelte compiles to direct DOM manipulation (no VDOM overhead). VDOM has overhead (diffing isn't free) — it's a tradeoff, not universally better.

Hard What is requestAnimationFrame and how is it different from setTimeout?

Answer: requestAnimationFrame (rAF) schedules a callback before the browser's next paint (typically 60fps = every 16.6ms). Unlike setTimeout(fn, 16): (1) rAF syncs with the display refresh rate (adaptive: 120Hz monitors get 120fps). (2) rAF pauses when tab is hidden (saves battery). (3) rAF batches with other visual updates (avoids partial frames). (4) Provides a high-precision timestamp argument. Use rAF for visual changes; setTimeout/setInterval for non-visual delays.

Hard What is the difference between HTMLElement and Element?

Answer: Element is the base class for ALL elements (HTML, SVG, MathML). HTMLElement extends Element specifically for HTML elements — adds: style property, dataset, contentEditable, draggable, hidden, click(), focus(), blur(). SVGElement extends Element differently. When working with SVG inside HTML, querySelector returns SVGElement (no .style.width — use setAttribute). Type narrowing: instanceof HTMLElement to check.

Hard Why is accessing offsetWidth/offsetHeight expensive?

Answer: These properties force a SYNCHRONOUS LAYOUT (reflow) if the DOM has been modified since the last layout. The browser must calculate the entire layout tree to give you an accurate answer. If you're in a read-write loop (layout thrashing), each read forces a full recalculation. Solution: batch reads first, then writes. Or cache the values. In DevTools Performance tab, these show up as "Forced reflow" purple warnings.

Expert Explain document.createTreeWalker — when would you use it?

Answer: TreeWalker traverses DOM efficiently with filtering. Much faster than recursive querySelector for specific traversal patterns. You define: rootNode, whatToShow filter (SHOW_ELEMENT, SHOW_TEXT, SHOW_COMMENT), and an optional NodeFilter function. Use cases: finding all text nodes for syntax highlighting, accessibility tree walking, custom DOM serializers, content extraction (ignoring scripts/styles). Performance: O(n) single pass vs querySelectorAll which creates a full list.

Expert What is the Range and Selection API?

Answer: Range represents a fragment of the document (between two boundary points — start/end containers + offsets). Selection represents what the user has selected. Use cases: rich text editors (bold selected text), highlight search results, programmatic text selection. Key methods: document.createRange(), window.getSelection(), range.surroundContents(). Gotcha: Range can span across elements — partial selections are tricky. Libraries like Quill, ProseMirror, TipTap use these extensively.

  set(key, value, ttlMs) {
    const item = {
      value,
      expiry: ttlMs ? Date.now() + ttlMs : null
    };

    return item.value;
  },

  remove(key) { localStorage.removeItem(key); },
  clear() { localStorage.clear(); }
};

🏋️ Exercise 7: Fetch Wrapper with Retry, Cache & Cancel

Expert Production-grade fetch utility:

class HttpClient {
  #cache = new Map();
  #pending = new Map();

  async request(url, options = {}) {
    const {
      method = "GET",
      body,
      headers = {},
      retries = 2,
      timeout = 10000,
      cache = false,
      cacheTTL = 60000,
      signal,
    } = options;

    // Check cache
    const cacheKey = `${method}:${url}`;
    if (cache && method === "GET") {
      const cached = this.#cache.get(cacheKey);
      if (cached && Date.now() - cached.time < cacheTTL) {
        return cached.data;
      }
    }

    // Deduplicate in-flight requests
    if (method === "GET" && this.#pending.has(cacheKey)) {
      return this.#pending.get(cacheKey);
    }

    const fetchPromise = this.#fetchWithRetry(url, {
      method,
      headers: { "Content-Type": "application/json", ...headers },
      body: body ? JSON.stringify(body) : undefined,
      signal: signal || AbortSignal.timeout(timeout),
    }, retries);

    if (method === "GET") {
      this.#pending.set(cacheKey, fetchPromise);
    }

    try {
      const data = await fetchPromise;
      if (cache && method === "GET") {
        this.#cache.set(cacheKey, { data, time: Date.now() });
      }
      return data;
    } finally {
      this.#pending.delete(cacheKey);
    }
  }

  async #fetchWithRetry(url, options, retries) {
    for (let attempt = 0; attempt <= retries; attempt++) {
      try {
        const res = await fetch(url, options);
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return await res.json();
      } catch (err) {
        if (err.name === "AbortError") throw err; // Don't retry aborts
        if (attempt === retries) throw err;
        await new Promise(r => setTimeout(r, 1000 * 2 ** attempt));
      }
    }
  }

  clearCache() { this.#cache.clear(); }
}

// Usage:
const http = new HttpClient();
const users = await http.request("/api/users", { cache: true, retries: 3 });

btn.addEventListener("click", (e) => {
  console.log("btn: handler 1 runs");
  e.stopPropagation(); // Stops bubbling to parent. BUT...
});

btn.addEventListener("click", () => {
  console.log("btn: handler 2 STILL runs"); // ← This runs!
});

parent.addEventListener("click", () => {
  console.log("parent: NEVER runs"); // ← Blocked by stopPropagation
});

 stopPropagation:   stops the event from traveling to OTHER elements,
                    but all handlers on the SAME element still fire.
*/

btn.addEventListener("click", (e) => {
  console.log("btn: handler 1 runs");
  e.stopImmediatePropagation(); // Stops propagation AND remaining handlers
});

btn.addEventListener("click", () => {
  console.log("btn: handler 2 NEVER runs"); // ← Also blocked!
});

parent.addEventListener("click", () => {
  console.log("parent: NEVER runs"); // ← Also blocked
});

/*
 stopImmediatePropagation: stops everything — no other handlers on
 the same element, and no bubbling to parents.

 Interview answer: Use stopPropagation when you want to cancel bubbling
 but let other listeners on the same element run. Use
 stopImmediatePropagation when you want to cancel absolutely everything.
*/

Use the capture phase to intercept ALL interactions across the page for analytics — without touching existing event handlers, and even catching events where a child calls stopPropagation().

// ── Why capture phase for analytics? ─────────────────────
// If a child element calls e.stopPropagation(), the bubble phase
// never reaches the document. Capture phase fires BEFORE any
// child handler, so it can't be silenced by child code.

const Analytics = (() => {
  const events = [];

  function track(type, target) {
    const entry = {
      type,
      tag: target.tagName,
      id: target.id || null,
      classes: [...target.classList].join(" ") || null,
      text: target.innerText?.slice(0, 60) || null,
      timestamp: Date.now(),
      path: target.closest("[data-track]")?.dataset.track || null,
    };
    events.push(entry);
    console.log("[Analytics]", entry);
  }

  // Attach in CAPTURE phase so nothing can block us
  document.addEventListener("click",   (e) => track("click", e.target), true);
  document.addEventListener("focus",   (e) => track("focus", e.target), true);
  document.addEventListener("submit",  (e) => track("submit", e.target), true);
  document.addEventListener("keydown", (e) => {
    if (e.key === "Enter") track("enter-key", e.target);
  }, true);

  return {
    getEvents: () => [...events],
    clearEvents: () => events.length = 0,
    flush: () => {
      // In production: POST to analytics endpoint, then clear
      console.table(events);
      events.length = 0;
    },
  };
})();
