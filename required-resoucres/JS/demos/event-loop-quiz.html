🧠 Event Loop Output Prediction

Predict the output order — tests microtask vs macrotask understanding

Q1: Basic Promise vs setTimeout

console.log('1'); setTimeout(() => console.log('2'), 0); Promise.resolve().then(() => console.log('3')); console.log('4');
1 → 4 → 3 → 2
Execution order:
1. console.log('1') — sync, runs immediately
2. setTimeout — schedules callback to macrotask queue
3. Promise.then — schedules callback to microtask queue
4. console.log('4') — sync, runs immediately
5. Call stack empty → drain microtask queue → '3'
6. Microtasks done → pick from macrotask queue → '2'
Rule: Microtasks ALWAYS run before the next macrotask.

Q2: Nested Promises

Promise.resolve().then(() => { console.log('A'); Promise.resolve().then(() => console.log('B')); }).then(() => console.log('C')); Promise.resolve().then(() => console.log('D'));
A → D → B → C
Microtask queue processing:
1. Two .then callbacks enqueued: [then→A, then→D]
2. Run then→A: logs 'A', enqueues then→B, returns (so next .then→C is enqueued)
3. Run then→D: logs 'D'
4. Queue now: [then→B, then→C]
5. Run then→B: logs 'B'
6. Run then→C: logs 'C'
Key: Inner .then gets enqueued during execution, but the next chained .then also gets enqueued at the same level.

Q3: async/await Desugaring

async function foo() { console.log('foo start'); await Promise.resolve(); console.log('foo end'); } console.log('script start'); foo(); console.log('script end');
script start → foo start → script end → foo end
await pauses the function, not the call stack:
1. 'script start' — sync
2. Call foo() — enters function, logs 'foo start'
3. await — pauses foo, schedules the rest as a microtask, returns to caller
4. 'script end' — sync (caller continues)
5. Call stack empty → microtask → 'foo end'
Key: Everything AFTER await is equivalent to putting it inside .then()

Q4: setTimeout vs Promise vs queueMicrotask

setTimeout(() => console.log('timeout'), 0); queueMicrotask(() => console.log('microtask')); Promise.resolve().then(() => console.log('promise')); console.log('sync');
sync → microtask → promise → timeout
Priority hierarchy:
1. Synchronous code runs first
2. queueMicrotask and Promise.then both go to microtask queue (FIFO order)
3. setTimeout goes to macrotask queue
4. All microtasks drain before any macrotask
Microtask sources: Promise.then, queueMicrotask, MutationObserver
Macrotask sources: setTimeout, setInterval, setImmediate, I/O, requestAnimationFrame

Q5: The Tricky One — async + setTimeout + Promise

async function async1() { console.log('async1 start'); await async2(); console.log('async1 end'); } async function async2() { console.log('async2'); } console.log('start'); setTimeout(() => console.log('timeout'), 0); async1(); new Promise((resolve) => { console.log('promise1'); resolve(); }).then(() => console.log('promise2')); console.log('end');
start → async1 start → async2 → promise1 → end → async1 end → promise2 → timeout
Step-by-step:
1. 'start' — sync
2. setTimeout enqueued to macrotask
3. Call async1: 'async1 start', then call async2: 'async2'
4. await pauses async1, schedules rest as microtask
5. new Promise executor is SYNC: 'promise1', resolve() → .then enqueued as microtask
6. 'end' — sync
7. Call stack empty → microtask queue: [async1-continuation, promise2]
8. 'async1 end', then 'promise2'
9. Macrotask: 'timeout'
