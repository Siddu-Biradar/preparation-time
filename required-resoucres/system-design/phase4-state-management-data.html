1. Understanding State Categories

Beginner

Theory: Types of State in Frontend Apps

// Every piece of data in your app falls into one of these categories:

┌─────────────────────────────────────────────────────────────────────────┐
│                         FRONTEND STATE MAP                              │
├───────────────────┬─────────────────────────────────────────────────────┤
│ SERVER STATE      │ Data that lives on backend, cached on client        │
│                   │ Examples: user profile, products, orders            │
│                   │ Tools: HTTP service + cache, NgRx Entity            │
├───────────────────┼─────────────────────────────────────────────────────┤
│ CLIENT STATE      │ UI-only data that doesn't exist on server           │
│                   │ Examples: sidebar open/closed, selected tab, theme  │
│                   │ Tools: Signals, Component state, localStorage       │
├───────────────────┼─────────────────────────────────────────────────────┤
│ FORM STATE        │ In-progress form data before submission             │
│                   │ Examples: draft email, checkout form, filters       │
│                   │ Tools: Reactive Forms, FormGroup                    │
├───────────────────┼─────────────────────────────────────────────────────┤
│ URL STATE         │ State encoded in the URL (shareable, bookmarkable)  │
│                   │ Examples: search query, pagination, filters, route  │
│                   │ Tools: Router, queryParams, ActivatedRoute          │
├───────────────────┼─────────────────────────────────────────────────────┤
│ SESSION STATE     │ Temporary state for current session                 │
│                   │ Examples: auth token, shopping cart, wizard progress│
│                   │ Tools: sessionStorage, in-memory service            │
└───────────────────┴─────────────────────────────────────────────────────┘

State Management Decision Matrix

ScenarioRecommended ApproachWhy
Component-local UI stateSignals / class fieldsSimple, no overhead, component-scoped
Shared across 2-3 componentsService with SignalsLightweight, injectable, tree-shakable
Complex domain (many entities)NgRx StorePredictable, time-travel debug, effects for side effects
Feature-scoped storeComponentStore / SignalStoreLightweight, no global registry
Server data cachingHTTP cache / SWR patternCache invalidation, loading states, retries
Form stateReactiveFormsModuleValidation, dirty tracking, nested groups
URL-persisted stateRouter queryParamsShareable, back/forward navigation works
Common Interview Mistake Don't say "We use NgRx for everything." Interviewers want to hear that you pick the right tool for the right state type. Global store for global state, local signals for local state, URL for shareable state.

2. Angular Signals (Modern State)

Critical

Theory: What Are Signals?

Signals (Angular 16+) are reactive primitives that hold a value and notify consumers when that value changes. They enable fine-grained reactivity without Zone.js.

// ═══ BASIC SIGNALS ═══
import { signal, computed, effect } from '@angular/core';

// Writable Signal — holds and updates a value:
const count = signal(0);           // Create
console.log(count());              // Read: 0
count.set(5);                      // Write (replace)
count.update(c => c + 1);         // Write (derive from previous)

// Computed Signal — derived, memoized, read-only:
const double = computed(() => count() * 2);
// Only recalculates when count() changes (memoized!)
// If count = 5, double() = 10 always (cached until count changes)

// Effect — side effect that runs when dependencies change:
effect(() => {
  console.log(`Count changed to: ${count()}`);
  // Automatically tracks which signals are read inside!
  // Re-runs whenever count() changes
});

// ═══ SIGNALS IN COMPONENTS (Angular 17+) ═══
@Component({
  template: `
    <h1>{{ title() }}</h1>
    <p>Items: {{ items().length }}</p>
    <p>Total: {{ total() }}</p>
    
    @for (item of filteredItems(); track item.id) {
      <app-item [item]="item" />
    }
  `
})
export class CartComponent {
  // Signal-based inputs (Angular 17.1+):
  title = input.required<string>();
  
  // Internal state:
  items = signal<CartItem[]>([]);
  filter = signal('');
  
  // Computed (auto-updates when items or filter change):
  filteredItems = computed(() => 
    this.items().filter(i => i.name.includes(this.filter()))
  );
  total = computed(() => 
    this.items().reduce((sum, i) => sum + i.price * i.qty, 0)
  );
  
  addItem(item: CartItem) {
    this.items.update(items => [...items, item]);
  }
  
  removeItem(id: string) {
    this.items.update(items => items.filter(i => i.id !== id));
  }
}

// ═══ SHARED STATE WITH SIGNAL SERVICE ═══
@Injectable({ providedIn: 'root' })
export class ThemeService {
  private _theme = signal<'light' | 'dark'>('light');
  
  // Expose read-only signal:
  readonly theme = this._theme.asReadonly();
  readonly isDark = computed(() => this._theme() === 'dark');
  
  toggle() {
    this._theme.update(t => t === 'light' ? 'dark' : 'light');
  }
}

NgRx SignalStore (Angular 17+)

// Feature-scoped, type-safe store built on Signals:
import { signalStore, withState, withComputed, withMethods, patchState } from '@ngrx/signals';
import { withEntities, addEntity, removeEntity } from '@ngrx/signals/entities';

type TodosState = { filter: 'all' | 'active' | 'completed'; loading: boolean };

export const TodosStore = signalStore(
  { providedIn: 'root' },
  withState<TodosState>({ filter: 'all', loading: false }),
  withEntities<Todo>(),  // Adds entities(), ids(), entityMap()
  withComputed((store) => ({
    filteredTodos: computed(() => {
      const todos = store.entities();
      switch (store.filter()) {
        case 'active': return todos.filter(t => !t.completed);
        case 'completed': return todos.filter(t => t.completed);
        default: return todos;
      }
    }),
    completedCount: computed(() => store.entities().filter(t => t.completed).length)
  })),
  withMethods((store, http = inject(HttpClient)) => ({
    setFilter(filter: 'all' | 'active' | 'completed') {
      patchState(store, { filter });
    },
    async loadTodos() {
      patchState(store, { loading: true });
      const todos = await firstValueFrom(http.get<Todo[]>('/api/todos'));
      patchState(store, setAllEntities(todos), { loading: false });
    },
    addTodo(todo: Todo) {
      patchState(store, addEntity(todo));
    },
    removeTodo(id: string) {
      patchState(store, removeEntity(id));
    }
  }))
);

// Usage in component:
@Component({
  providers: [TodosStore],  // or use providedIn: 'root'
  template: `
    @if (store.loading()) { <app-spinner /> }
    @for (todo of store.filteredTodos(); track todo.id) {
      <app-todo-item [todo]="todo" (delete)="store.removeTodo(todo.id)" />
    }
    <p>Completed: {{ store.completedCount() }}</p>
  `
})
export class TodosComponent {
  readonly store = inject(TodosStore);
  
  ngOnInit() { this.store.loadTodos(); }
}

3. NgRx Store (Redux Pattern)

Advanced

Theory: When to Use NgRx

Use NgRx When
  • Multiple components share the same data (global cart, user session, notifications)
  • Complex data flows with many side effects (API calls, WebSocket events)
  • Need time-travel debugging, action logging, state snapshots
  • Team wants strict, predictable architecture (enterprise apps)
// ═══ NgRx Architecture ═══
//
// ┌──────────┐    dispatch     ┌──────────┐    pure function   ┌───────────┐
// │Component │ ──────────────→ │  Action  │ ─────────────────→ │  Reducer  │
// │          │                 {type,data}│                    │ (state,a) │
// └──────────┘                 └──────────┘                    └─────┬─────┘
//       ↑                                                            │
//       │ select                                                     ↓ new state
//       │                                                     ┌───────────┐
//       └──────────────────── Selector ←──────────────────────│   Store   │
//                              (memoized query)               └───────────┘
//                                                                    ↑
//                              ┌──────────┐  side effects     ┌─────┴─────┐
//                              │  Effect  │ ←─────────────────│  Actions$ │
//                              │(API call)│                   └───────────┘
//                              └──────────┘

// ═══ ACTIONS ═══
// actions/product.actions.ts
export const ProductActions = createActionGroup({
  source: 'Product',
  events: {
    'Load Products': props<{ category: string }>(),
    'Load Products Success': props<{ products: Product[] }>(),
    'Load Products Failure': props<{ error: string }>(),
    'Add To Cart': props<{ productId: string; qty: number }>(),
  }
});

// ═══ REDUCER ═══
// reducers/product.reducer.ts
export interface ProductState {
  products: Product[];
  loading: boolean;
  error: string | null;
}

const initialState: ProductState = { products: [], loading: false, error: null };

export const productReducer = createReducer(
  initialState,
  on(ProductActions.loadProducts, (state) => ({ ...state, loading: true, error: null })),
  on(ProductActions.loadProductsSuccess, (state, { products }) => ({
    ...state, products, loading: false
  })),
  on(ProductActions.loadProductsFailure, (state, { error }) => ({
    ...state, error, loading: false
  }))
);

// ═══ SELECTORS (Memoized queries) ═══
export const selectProductState = createFeatureSelector<ProductState>('products');
export const selectAllProducts = createSelector(selectProductState, s => s.products);
export const selectLoading = createSelector(selectProductState, s => s.loading);
export const selectProductsByCategory = (category: string) =>
  createSelector(selectAllProducts, products => products.filter(p => p.category === category));

// ═══ EFFECTS (Side effects — API calls) ═══
@Injectable()
export class ProductEffects {
  private actions$ = inject(Actions);
  private http = inject(HttpClient);

  loadProducts$ = createEffect(() =>
    this.actions$.pipe(
      ofType(ProductActions.loadProducts),
      switchMap(({ category }) =>
        this.http.get<Product[]>(`/api/products?category=${category}`).pipe(
          map(products => ProductActions.loadProductsSuccess({ products })),
          catchError(error => of(ProductActions.loadProductsFailure({ error: error.message })))
        )
      )
    )
  );
}

// ═══ COMPONENT ═══
@Component({
  template: `
    @if (loading$ | async) { <app-spinner /> }
    @for (product of products$ | async; track product.id) {
      <app-product-card [product]="product" (addToCart)="addToCart($event)" />
    }
  `
})
export class ProductListComponent {
  private store = inject(Store);
  products$ = this.store.select(selectAllProducts);
  loading$ = this.store.select(selectLoading);
  
  ngOnInit() {
    this.store.dispatch(ProductActions.loadProducts({ category: 'electronics' }));
  }
  
  addToCart(productId: string) {
    this.store.dispatch(ProductActions.addToCart({ productId, qty: 1 }));
  }
}

4. ComponentStore (Lightweight Local Store)

Intermediate 
// ComponentStore = local store for a SINGLE feature/component
// No global registry, no actions, no effects boilerplate
// Perfect for: search with filters, wizard steps, feature-specific state

@Injectable()
export class SearchStore extends ComponentStore<SearchState> {
  constructor(private http: HttpClient) {
    super({ query: '', results: [], loading: false, page: 1 });
  }

  // Selectors:
  readonly results$ = this.select(s => s.results);
  readonly loading$ = this.select(s => s.loading);
  readonly vm$ = this.select(s => ({
    results: s.results,
    loading: s.loading,
    hasMore: s.results.length >= 20
  }));

  // Updaters (synchronous state changes):
  readonly setQuery = this.updater((state, query: string) => ({
    ...state, query, page: 1
  }));

  // Effects (async operations):
  readonly search = this.effect<string>(query$ =>
    query$.pipe(
      debounceTime(300),
      distinctUntilChanged(),
      tap(() => this.patchState({ loading: true })),
      switchMap(query =>
        this.http.get<Product[]>(`/api/search?q=${query}`).pipe(
          tapResponse(
            results => this.patchState({ results, loading: false }),
            error => this.patchState({ loading: false })
          )
        )
      )
    )
  );
}

// Component:
@Component({
  providers: [SearchStore],  // Scoped to component lifetime!
  template: `
    <input (input)="onSearch($event)" />
    <ng-container *ngIf="store.vm$ | async as vm">
      <app-spinner *ngIf="vm.loading" />
      <app-results [items]="vm.results" />
    </ng-container>
  `
})
export class SearchComponent {
  store = inject(SearchStore);
  onSearch(event: Event) {
    this.store.search((event.target as HTMLInputElement).value);
  }
}

5. RxJS State Patterns

Intermediate 
// ═══ BehaviorSubject Service (Simple shared state) ═══
@Injectable({ providedIn: 'root' })
export class CartService {
  private items$ = new BehaviorSubject<CartItem[]>([]);
  
  // Public observables (read-only):
  readonly cart$ = this.items$.asObservable();
  readonly itemCount$ = this.cart$.pipe(map(items => items.length));
  readonly total$ = this.cart$.pipe(
    map(items => items.reduce((sum, i) => sum + i.price * i.qty, 0))
  );
  
  addItem(item: CartItem) {
    const current = this.items$.getValue();
    const existing = current.find(i => i.id === item.id);
    if (existing) {
      this.items$.next(current.map(i => 
        i.id === item.id ? { ...i, qty: i.qty + 1 } : i
      ));
    } else {
      this.items$.next([...current, { ...item, qty: 1 }]);
    }
  }
  
  removeItem(id: string) {
    this.items$.next(this.items$.getValue().filter(i => i.id !== id));
  }
}

// ═══ SCAN PATTERN (Event sourcing style) ═══
interface CartEvent {
  type: 'add' | 'remove' | 'clear' | 'updateQty';
  payload?: any;
}

@Injectable({ providedIn: 'root' })
export class CartEventService {
  private events$ = new Subject<CartEvent>();
  
  readonly cart$ = this.events$.pipe(
    scan((state: CartItem[], event: CartEvent) => {
      switch (event.type) {
        case 'add': return [...state, event.payload];
        case 'remove': return state.filter(i => i.id !== event.payload);
        case 'updateQty': return state.map(i => 
          i.id === event.payload.id ? { ...i, qty: event.payload.qty } : i
        );
        case 'clear': return [];
      }
    }, []),
    shareReplay(1)
  );
  
  dispatch(event: CartEvent) { this.events$.next(event); }
}

// ═══ combineLatest for DERIVED STATE ═══
// When you need state that depends on multiple sources:
readonly vm$ = combineLatest([
  this.products$,
  this.filters$,
  this.sort$
]).pipe(
  map(([products, filters, sort]) => ({
    products: this.applyFilters(products, filters, sort),
    activeFilters: Object.keys(filters).filter(k => filters[k]),
    total: products.length
  })),
  shareReplay(1)
);

6. Data Normalization

Advanced 
// ═══ PROBLEM: Nested/duplicated data ═══
// API returns:
{
  posts: [
    { id: 1, title: "...", author: { id: 5, name: "Alice" }, comments: [...] },
    { id: 2, title: "...", author: { id: 5, name: "Alice" }, comments: [...] }
  ]
}
// "Alice" is duplicated! If her name changes, update in 50 places?

// ═══ SOLUTION: Normalize (flat structure with IDs) ═══
// Normalized state:
{
  entities: {
    posts: {
      1: { id: 1, title: "...", authorId: 5, commentIds: [10, 11] },
      2: { id: 2, title: "...", authorId: 5, commentIds: [12] }
    },
    users: {
      5: { id: 5, name: "Alice" }
    },
    comments: {
      10: { id: 10, text: "...", authorId: 5 },
      11: { id: 11, text: "...", authorId: 7 },
      12: { id: 12, text: "...", authorId: 5 }
    }
  },
  ids: {
    posts: [1, 2],
    users: [5, 7],
    comments: [10, 11, 12]
  }
}
// Now "Alice" exists in ONE place. Update once → reflected everywhere!

// ═══ NgRx Entity (Built-in normalization) ═══
import { EntityState, createEntityAdapter } from '@ngrx/entity';

interface ProductState extends EntityState<Product> {
  selectedId: string | null;
  loading: boolean;
}

const adapter = createEntityAdapter<Product>({
  selectId: product => product.id,
  sortComparer: (a, b) => a.name.localeCompare(b.name)
});

const initialState: ProductState = adapter.getInitialState({
  selectedId: null,
  loading: false
});

// Reducer with adapter methods:
export const productReducer = createReducer(
  initialState,
  on(ProductActions.loadSuccess, (state, { products }) =>
    adapter.setAll(products, { ...state, loading: false })
  ),
  on(ProductActions.addOne, (state, { product }) =>
    adapter.addOne(product, state)
  ),
  on(ProductActions.updateOne, (state, { id, changes }) =>
    adapter.updateOne({ id, changes }, state)
  ),
  on(ProductActions.removeOne, (state, { id }) =>
    adapter.removeOne(id, state)
  )
);

// Selectors (adapter provides built-in):
const { selectAll, selectEntities, selectIds, selectTotal } = adapter.getSelectors();
export const selectAllProducts = createSelector(selectProductState, selectAll);
export const selectProductById = (id: string) =>
  createSelector(selectProductState, state => state.entities[id]);

7. Optimistic UI Updates

Advanced 
// ═══ THEORY ═══
// PESSIMISTIC: Click → Loading... → Wait for server → Show result
// OPTIMISTIC:  Click → Show result immediately → Sync with server in background
//              If server fails → ROLLBACK to previous state

// User PERCEIVES instant response! (Like, favorite, delete, reorder)

// ═══ IMPLEMENTATION ═══
@Injectable()
export class OptimisticTodoService {
  private todos = signal<Todo[]>([]);
  readonly todos$ = this.todos.asReadonly();
  
  // Optimistic Delete:
  async deleteTodo(id: string) {
    // 1. Save current state for rollback:
    const previousTodos = this.todos();
    
    // 2. Optimistically remove immediately:
    this.todos.update(todos => todos.filter(t => t.id !== id));
    
    try {
      // 3. Sync with server:
      await firstValueFrom(this.http.delete(`/api/todos/${id}`));
    } catch (error) {
      // 4. ROLLBACK on failure:
      this.todos.set(previousTodos);
      this.snackbar.open('Failed to delete. Please try again.', 'Dismiss');
    }
  }
  
  // Optimistic Add:
  async addTodo(text: string) {
    const tempId = `temp-${Date.now()}`;
    const optimisticTodo = { id: tempId, text, completed: false, pending: true };
    
    // Show immediately with pending indicator:
    this.todos.update(todos => [...todos, optimisticTodo]);
    
    try {
      const savedTodo = await firstValueFrom(
        this.http.post<Todo>('/api/todos', { text })
      );
      // Replace temp with real:
      this.todos.update(todos => todos.map(t => t.id === tempId ? savedTodo : t));
    } catch {
      // Remove optimistic entry:
      this.todos.update(todos => todos.filter(t => t.id !== tempId));
      this.snackbar.open('Failed to add todo.', 'Retry');
    }
  }
}

// ═══ NgRx Optimistic Pattern ═══
// 1. Reducer handles action immediately (optimistic)
// 2. Effect calls API
// 3. On failure: dispatch rollback action
loadProducts$ = createEffect(() =>
  this.actions$.pipe(
    ofType(ProductActions.deleteProduct),
    mergeMap(({ id, previousState }) =>
      this.http.delete(`/api/products/${id}`).pipe(
        map(() => ProductActions.deleteProductSuccess({ id })),
        catchError(() => of(ProductActions.deleteProductRollback({ previousState })))
      )
    )
  )
);

@Component({

// ═══ FORM AUTO-SAVE (Draft persistence) ═══
@Injectable({ providedIn: 'root' })
export class FormPersistService {
  save(key: string, formValue: any) {
    sessionStorage.setItem(`form_${key}`, JSON.stringify(formValue));
  }
  
  restore(key: string): any | null {
    const saved = sessionStorage.getItem(`form_${key}`);
    return saved ? JSON.parse(saved) : null;
  }
  
  clear(key: string) { sessionStorage.removeItem(`form_${key}`); }
}

// In component:
ngOnInit() {
  const saved = this.formPersist.restore('checkout');
  if (saved) this.form.patchValue(saved);
  
  // Auto-save on changes (debounced):
  this.form.valueChanges.pipe(
    debounceTime(1000),
    takeUntilDestroyed()
  ).subscribe(value => this.formPersist.save('checkout', value));
}

onSubmit() {
  this.formPersist.clear('checkout'); // Clear draft on successful submit
}

9. URL as State (Router State)

Intermediate 
// ═══ WHY USE URL FOR STATE? ═══
// 1. Shareable — copy URL and send to colleague
// 2. Bookmarkable — save filtered view
// 3. Back/Forward works — browser history integration
// 4. SEO — search engines can crawl different states

// ═══ Query Params for Filters ═══
// URL: /products?category=electronics&sort=price&page=2&q=laptop
@Component({
  template: `
    <input [value]="query()" (input)="updateQuery($event)" />
    <select (change)="updateSort($event)">...</select>
  `
})
export class ProductsComponent {
  private route = inject(ActivatedRoute);
  private router = inject(Router);
  
  // Read params reactively:
  query = toSignal(this.route.queryParamMap.pipe(
    map(params => params.get('q') || '')
  ));
  
  category = toSignal(this.route.queryParamMap.pipe(
    map(params => params.get('category') || 'all')
  ));
  
  // Update URL (without reloading component):
  updateQuery(event: Event) {
    const q = (event.target as HTMLInputElement).value;
    this.router.navigate([], {
      relativeTo: this.route,
      queryParams: { q, page: 1 },  // Reset page on new search
      queryParamsHandling: 'merge'   // Keep other params
    });
  }
  
  updateSort(event: Event) {
    this.router.navigate([], {
      relativeTo: this.route,
      queryParams: { sort: (event.target as HTMLSelectElement).value },
      queryParamsHandling: 'merge'
    });
  }
}

// URL: /products/123/reviews

import { openDB } from 'idb';

@Injectable({ providedIn: 'root' })
export class OfflineStorageService {
  private dbPromise = openDB('myApp', 1, {
    upgrade(db) {
      db.createObjectStore('products', { keyPath: 'id' });
      db.createObjectStore('cart', { keyPath: 'id' });
      const syncStore = db.createObjectStore('syncQueue', { autoIncrement: true });
      syncStore.createIndex('timestamp', 'timestamp');
    }
  });
  
  async saveProducts(products: Product[]) {
    const db = await this.dbPromise;
    const tx = db.transaction('products', 'readwrite');
    await Promise.all(products.map(p => tx.store.put(p)));
    await tx.done;
  }
  
  async getProducts(): Promise<Product[]> {
    const db = await this.dbPromise;
    return db.getAll('products');
  }
  
  // Queue operations for sync when online:
  async queueForSync(operation: { method: string; url: string; body?: any }) {
    const db = await this.dbPromise;
    await db.add('syncQueue', { ...operation, timestamp: Date.now() });
  }
  
  async processSyncQueue() {
    const db = await this.dbPromise;
    const items = await db.getAll('syncQueue');
    for (const item of items) {
      try {
        await fetch(item.url, { method: item.method, body: JSON.stringify(item.body) });
        await db.delete('syncQueue', item.id);
      } catch { break; } // Stop if still offline
    }
  }
}

12. Interview Questions (Previously Asked)

Q1: When would you use NgRx vs a simple service with BehaviorSubject? (All companies)

Answer: BehaviorSubject service: 2-5 components sharing state, simple data flows, no side effects. NgRx: complex domain with many entities, multiple components dispatching actions, side effects (API, WebSocket), need action logging/debugging, team of 5+ developers needing conventions. Middle ground: ComponentStore for feature-scoped complexity without global overhead. Modern Angular: SignalStore for most cases (simpler API, Signal integration). Rule: start simple (Signals), grow to NgRx only when you feel pain.

Q2: How do you implement optimistic UI updates? What about conflict resolution? (Amazon, Flipkart)

Answer: Optimistic: (1) Save previous state. (2) Apply change immediately in UI. (3) Send to server in background. (4) On failure: rollback + notify user. Conflict resolution: (a) Last-write-wins: simplest, server timestamp decides. (b) Version field (ETag/optimistic locking): reject if version mismatch, show conflict UI. (c) Operational Transform: for collaborative editing (complex). (d) CRDTs: conflict-free replicated data types for offline-first. Shopping cart example: server is source of truth, client merges on reconnect.

Q3: Explain data normalization in frontend state. Why is it important? (Google, Microsoft)

Answer: Normalization = storing entities in flat maps (by ID) instead of nested structures. Benefits: (1) Single source of truth — update user name in one place, reflected everywhere. (2) O(1) lookups by ID. (3) Avoids data duplication (same user in 50 posts). (4) Easier updates (no deep cloning nested objects). (5) Efficient selectors (memoized). NgRx Entity provides this out of the box. Trade-off: denormalization for read-heavy views (selector joins data). Similar to database normal forms.

Q4: How would you handle offline-first architecture in a frontend app? (Swiggy, PhonePe)

Answer: Architecture: (1) IndexedDB as local database (structured, large capacity). (2) Service Worker for network interception (serve cached responses). (3) Background Sync API for queuing mutations while offline. (4) Sync engine: on reconnect, send queued operations in order. (5) Conflict resolution strategy (timestamp-based or server-wins). (6) UI indicators: online/offline badge, "syncing..." status, "last synced: 5m ago". (7) Optimistic UI: always show local state, mark unsynced items. Example: Todo app that works offline, syncs when back.

Q5: What are Angular Signals and how do they differ from RxJS Observables? (Angular-focused companies)

Answer: Signals: synchronous, always have a current value, pull-based (read when needed), automatically tracked dependencies, no subscription management, fine-grained template updates. Observables: async streams, push-based, require subscribe/unsubscribe, powerful operators (debounce, merge, switchMap), handle events over time. Use Signals for: synchronous state, template bindings, computed values. Use RxJS for: HTTP calls, event streams, time-based operations, complex async coordination. They coexist: toSignal()/toObservable() bridge them.
