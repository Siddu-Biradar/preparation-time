Core Angular

Q: What is the difference between a Component and a Directive?

Answer

A Component is a Directive WITH a template. Every component is technically a directive, but with associated HTML. A Directive modifies behavior/appearance of existing DOM elements without its own template.

  • Component: @Component({ template: '...' }) — has its own view
  • Structural Directive: @Directive({ selector: '[appIf]' }) — adds/removes DOM
  • Attribute Directive: @Directive({ selector: '[appHighlight]' }) — modifies existing element

Q: Explain Angular's change detection. How does Zone.js fit in?

Answer

Change detection is Angular's mechanism to keep the DOM in sync with component state. Zone.js monkey-patches async APIs (setTimeout, Promises, events) to notify Angular when "something happened." Angular then runs change detection from root to leaves, checking all template bindings.

Default strategy: Checks ALL components top-down on every trigger.

OnPush strategy: Skips component unless: @Input reference changes, event from component/child, async pipe emits, or markForCheck() called.

Zoneless (Angular 18+): No Zone.js. Change detection driven by signals — Angular knows exactly which component's template to update.

Q: What's the difference between constructor and ngOnInit?

Answer

Constructor: TypeScript class constructor. Called when DI creates the instance. @Input values are NOT available yet. Use only for DI assignment.

ngOnInit: Angular lifecycle hook. Called once AFTER first ngOnChanges (after @Input bindings are set). Use for initialization logic, API calls, setting up subscriptions.

constructor(private service: MyService) {
  // this.myInput is undefined here!
}
ngOnInit() {
  // this.myInput has its value here
  this.service.load(this.myInput);
}

Q: How does Dependency Injection work in Angular?

Answer

Angular's DI is a hierarchical injector system. When a class requests a dependency, Angular looks up the injector tree (Element Injector hierarchy first, then Module Injector hierarchy) to find a provider. The injector creates/returns the singleton instance for that scope.

Key concepts: Token (what to look for), Provider (how to create it), Injector (container that holds instances).

Registration methods: providedIn: 'root' (tree-shakable singleton), component providers (new instance per component), route providers (scoped to route).

Q: Explain ViewEncapsulation modes.

Answer
  • Emulated (default): Angular adds unique attributes (_ngcontent-xxx) to component elements and rewrites CSS selectors to scope styles. Not real Shadow DOM but achieves similar isolation.
  • ShadowDom: Uses native Shadow DOM. True style isolation. External styles don't leak in, component styles don't leak out. Best isolation but limited browser support for older versions.
  • None: No encapsulation. Styles are global — affect entire app. Use for global themes or utility classes.

RxJS & Async

Q: Explain switchMap vs mergeMap vs concatMap vs exhaustMap

Answer
  • switchMap: Cancels previous inner observable when new emission arrives. Use for: search typeahead, route-based data loading.
  • mergeMap: Runs all inner observables concurrently (no cancellation). Use for: parallel uploads, independent actions.
  • concatMap: Queues inner observables — waits for previous to complete. Use for: sequential operations where order matters.
  • exhaustMap: Ignores new emissions while current inner is still running. Use for: login button, form submit (prevent double-click).

Q: How do you prevent memory leaks from observables?

Answer
  1. async pipe — Auto-subscribes/unsubscribes in template (best approach)
  2. takeUntilDestroyed() — Angular 16+ (cleanest in component class)
  3. DestroyRef + takeUntilDestroyed(ref) — For code outside injection context
  4. takeUntil(destroy$) — Pre-Angular 16 pattern with Subject
  5. Subscription management — Store subscription, call .unsubscribe() in ngOnDestroy

You DON'T need to unsubscribe from: HTTP calls (complete after response), finite observables (of, from array), router observables in routed components.

Q: What is the async pipe? Why is it considered a best practice?

Answer

The async pipe subscribes to an Observable/Promise, returns the latest value, and automatically unsubscribes when the component is destroyed. Benefits:

  • No manual subscription management (no memory leaks)
  • Works with OnPush change detection (calls markForCheck internally)
  • Cleaner templates (no component property needed)
  • Handles null/undefined gracefully
// Before: manual subscription (error-prone)
ngOnInit() { this.sub = this.data$.subscribe(d => this.data = d); }
ngOnDestroy() { this.sub.unsubscribe(); }

// After: async pipe (clean)
template: `@if (data$ | async; as data) { {{ data.title }} }`

Performance & Optimization

Q: Why shouldn't you call functions in Angular templates?

Answer

Functions in templates run on EVERY change detection cycle. With default CD, a function like {{ getTotal() }} runs potentially dozens of times per second (on every click, mousemove, timer, etc.).

Solutions:

  • Use a pure pipe — only recalculates when input reference changes
  • Use computed() signal — memoized, only recalculates when dependencies change
  • Pre-compute in the component and store in a property
// BAD
{{ getFilteredItems().length }}

// GOOD — computed signal
filteredCount = computed(() => this.items().filter(i => i.active).length);
// Template: {{ filteredCount() }}

// GOOD — pure pipe
// Template: {{ items | filter:'active' | count }}

Q: How does lazy loading work? What are the benefits?

Answer

Lazy loading splits your app into chunks that load on-demand when the user navigates to specific routes. Instead of loading the entire app upfront (large initial bundle), only the code needed for the current view is loaded.

{ path: 'admin', loadComponent: () => import('./admin.component').then(m => m.AdminComponent) }

Benefits: Faster initial load, smaller initial bundle, users only download what they use.

@defer: Angular 17+ adds component-level lazy loading (load on viewport, interaction, hover, timer).

Q: What is OnPush change detection? When would a component NOT re-render?

Answer

OnPush tells Angular to skip this component during CD unless specific triggers occur:

WILL trigger CD:

  1. @Input reference changes (new object, not mutation)
  2. Event originates from this component or its children
  3. Async pipe receives new value
  4. Signal read in template changes
  5. markForCheck() or detectChanges() called manually

WON'T trigger: Parent CD running (if inputs unchanged), setTimeout in a service, object mutation (this.items.push()), BehaviorSubject.next() without async pipe.

Modern Angular (Signals & v17+)

Q: What are Angular Signals? How do they compare to RxJS?

Answer

Signals are synchronous reactive primitives. They hold a value and notify consumers when it changes. Unlike Observables (push-based, async), signals are pull-based and synchronous.

SignalsRxJS
Synchronous read: value()Async: .subscribe()
Always have a valueMay not have emitted yet
No unsubscription neededMust unsubscribe
Simple state managementComplex async orchestration
Fine-grained reactivityStream transformation

Use Signals for: UI state, component state, simple derived state.

Use RxJS for: HTTP requests, WebSockets, complex async flows, debouncing, retry logic, race conditions.

Q: What is the @defer block? How does it improve performance?

Answer

@defer enables component-level code splitting and lazy loading without routing. The deferred component's code is in a separate JS chunk that only loads when the trigger condition is met.

@defer (on viewport; prefetch on idle) {
  <app-heavy-chart />
} @placeholder {
  <div style="height:300px"></div>
} @loading (minimum 200ms) {
  <app-spinner />
}

Triggers: on viewport, on interaction, on hover, on idle, on timer(5s), when condition.

Performance benefit: Initial bundle doesn't include deferred components — they load only when needed, reducing Time to Interactive.

Architecture & Design

Q: How would you architect a large-scale Angular application?

Answer
  • Core module/folder: Singleton services, guards, interceptors, models
  • Shared module/folder: Reusable components, directives, pipes
  • Feature folders: Each feature is self-contained, lazy-loaded via routes
  • Smart/Dumb pattern: Container components handle logic; presentational components are pure UI
  • State management: NgRx for complex, signals/services for simple
  • Strict typing: Interfaces for all API responses, no any
  • OnPush everywhere: Performance by default
  • Nx monorepo: For multiple apps sharing libraries
  • Barrel exports: index.ts in each module for clean imports
  • Environment configs: Different configs for dev/staging/prod

Q: How do you handle authentication in an Angular SPA?

Answer
  1. Login: POST credentials to API → receive JWT (access + refresh token)
  2. Storage: HttpOnly cookies (most secure) or in-memory (sessionStorage for refresh)
  3. Interceptor: Attach Bearer token to every API request
  4. Token refresh: Interceptor detects 401, uses refresh token to get new access token, retries failed request
  5. Route guards: canActivate checks if user is authenticated + has required role
  6. Auto-logout: On token expiry or inactivity timeout
// Auth interceptor with token refresh
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const auth = inject(AuthService);
  const token = auth.getAccessToken();
  
  const authReq = token 
    ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })
    : req;

  return next(authReq).pipe(
    catchError(err => {
      if (err.status === 401 && !req.url.includes('/refresh')) {
        return auth.refreshToken().pipe(
          switchMap(newToken => {
            const retryReq = req.clone({
              setHeaders: { Authorization: `Bearer ${newToken}` }
            });
            return next(retryReq);
          })
        );
      }
      return throwError(() => err);
    })
  );
};

Q: Explain the Ivy renderer. What problems did it solve?

Answer

Ivy is Angular's compilation and rendering engine (default since Angular 9, replaced View Engine). Key improvements:

  • Smaller bundles: Better tree-shaking. Unused Angular features are removed from bundle.
  • Faster compilation: Each component compiled independently (locality principle). Faster rebuilds.
  • Better debugging: Component classes are directly debuggable (no generated wrapper code).
  • Dynamic components simplified: No more entryComponents or ComponentFactoryResolver.
  • Template type checking: Strict mode catches template errors at build time.
  • Lazy-loading improvements: Components can be lazy-loaded without NgModule.

Tricky Questions

Q: What happens if two components provide the same service in their providers array?

Answer

Each component gets its OWN instance of the service. Angular's hierarchical DI creates a new instance at each provider registration point. Children of each component share their parent's instance (unless they also provide it).

// ParentA providers: [MyService]  → Instance A
//   ChildA (no providers) → uses Instance A
// ParentB providers: [MyService]  → Instance B (different!)
//   ChildB (no providers) → uses Instance B

Q: Can you use two structural directives on the same element?

Answer

No. Each element can only have ONE structural directive (because each desugars to an ng-template wrapper). Solutions:

// Problem: *ngIf and *ngFor on same element — ERROR
<li *ngIf="show" *ngFor="let item of items"> ✗

// Solution 1: ng-container
<ng-container *ngIf="show">
  <li *ngFor="let item of items">{{ item }}</li>
</ng-container>

// Solution 2: New control flow (Angular 17+) — no restriction
@if (show) {
  @for (item of items; track item.id) {
    <li>{{ item }}</li>
  }
}

Q: What is ExpressionChangedAfterItHasBeenCheckedError?

Answer

This error occurs in development mode when Angular's second CD pass (verification pass) detects that a value changed AFTER it was already rendered. Angular runs CD twice in dev mode to catch this.

Common causes:

  • Modifying parent state from child's lifecycle hooks (e.g., in ngAfterViewInit)
  • Service updating shared state during CD cycle
  • Getters that return new object references each time

Fixes: Use setTimeout (moves to next CD cycle), use ChangeDetectorRef.detectChanges() after change, restructure to avoid child→parent data flow during CD, use signals.

Q: What is the difference between providers and viewProviders?

Answer

providers: Service available to the component, its view children, AND projected content (ng-content).

viewProviders: Service available to the component and its view children ONLY. Projected content CANNOT access it.

Use case: When you want to provide a service to your component's internal template but hide it from consumers who project content into your component.

Q: How does Angular handle security (XSS, CSRF)?

Answer

XSS Protection:

  • All interpolation ({{ }}) is automatically sanitized — HTML entities escaped
  • [innerHTML] binding is sanitized (scripts, event handlers stripped)
  • AOT compilation prevents template injection (no eval)
  • DomSanitizer provides bypass methods for TRUSTED content only

CSRF Protection:

  • HttpClient automatically reads XSRF-TOKEN cookie and sends X-XSRF-TOKEN header
  • Configurable via provideHttpClient(withXsrfConfiguration(...))
