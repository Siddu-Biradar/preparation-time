1. Zone.js — How Angular Knows When to Update

What is Zone.js?

Zone.js is a library that monkey-patches all async browser APIs (setTimeout, Promise, addEventListener, XHR, fetch, etc.) to notify Angular when async operations happen. Angular uses this to know when to run change detection.

What Zone.js Patches

// Zone.js intercepts ALL of these:
setTimeout / setInterval / clearTimeout / clearInterval
Promise.then / catch / finally
addEventListener / removeEventListener
XMLHttpRequest (open, send)
fetch
requestAnimationFrame
MutationObserver
WebSocket (onmessage, onerror)
// ... and more

// What happens when you click a button:
// 1. Click event fires
// 2. Zone.js detects async event completed
// 3. Zone.js notifies Angular: "Something happened!"
// 4. Angular runs change detection from ROOT to ALL components
// 5. DOM updated where bindings changed

NgZone

@Injectable({ providedIn: 'root' })
export class PerformanceService {
  private ngZone = inject(NgZone);

  // Run code OUTSIDE Angular zone (won't trigger change detection)
  initHeavyAnimation() {
    this.ngZone.runOutsideAngular(() => {
      // This interval won't trigger change detection on every tick
      setInterval(() => {
        this.updateCanvasAnimation();  // DOM manipulation without Angular overhead
      }, 16);  // 60fps
    });
  }

  // When you need to come BACK into Angular zone
  notifyAngular(data: any) {
    this.ngZone.run(() => {
      // This WILL trigger change detection
      this.data = data;
    });
  }
}

2. Change Detection Mechanism

How Change Detection Works

// Angular's CD algorithm (simplified):
// 1. Start at root component
// 2. For EACH component in the tree (top-down):
//    a. Update input bindings
//    b. Run ngOnChanges (if inputs changed)
//    c. Run ngDoCheck
//    d. Update DOM bindings (check if {{ expression }} values changed)
//    e. Run ngAfterContentChecked
//    f. Run ngAfterViewChecked
//    g. Move to child components
// 3. After full tree checked, DOM is up to date

// With DEFAULT strategy:
// EVERY component is checked on EVERY trigger
// Even if nothing changed in that component!

// Component tree:
//     AppComponent          ← checked
//     ├── HeaderComponent   ← checked  
//     ├── SidebarComponent  ← checked
//     └── MainComponent     ← checked
//         ├── ListComponent ← checked
//         │   ├── Item1     ← checked
//         │   ├── Item2     ← checked
//         │   └── Item3     ← checked
//         └── FooterComponent ← checked
// One click anywhere → ALL 9 components checked!

3. Default vs OnPush Strategy

AspectDefaultOnPush
TriggerAny async event (Zone.js)Only specific triggers (see below)
ScopeCheck component + all descendantsSkip unless triggered
PerformanceCan be slow with many componentsMuch faster — checks only when needed
Immutability requiredNo (detects mutations)YES (must create new references)
Best forSimple apps, prototypesProduction apps, performance-critical
@Component({
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <h2>{{ user.name }}</h2>
    <p>{{ user.email }}</p>
  `
})
export class UserCardComponent {
  @Input() user!: User;
}

// Parent with Default:
// This WON'T update UserCard (same object reference!):
this.user.name = 'New Name';  // ❌ Mutation — OnPush won't detect

// This WILL update UserCard (new reference):
this.user = { ...this.user, name: 'New Name' };  // ✓ New object

4. OnPush Deep Dive — When Does It Check?

An OnPush component is checked ONLY when:

  1. @Input reference changes — New object/array reference (not mutation)
  2. Event from the component or its children — (click), (keyup), etc.
  3. Async pipe emits a new value — The pipe calls markForCheck()
  4. Manual markForCheck() / detectChanges() — You explicitly tell Angular
  5. Signal value changes — (Angular 17+ with signals in template)
// Things that WON'T trigger OnPush CD:
// - setTimeout/setInterval (unless inside the component itself + Zone.js)
// - Service method modifying a property (unless you markForCheck)
// - Parent's CD running (won't cascade down if inputs unchanged)

// Common pattern with OnPush + Observables:
@Component({
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <!-- async pipe handles markForCheck automatically! -->
    @if (user$ | async; as user) {
      <h1>{{ user.name }}</h1>
      <p>{{ user.email }}</p>
    }
    
    @for (item of items$ | async; track item.id) {
      <app-item [data]="item" />
    }
  `
})
export class SmartComponent {
  user$ = this.userService.currentUser$;
  items$ = this.itemService.getItems();
  // No manual subscription needed!
  // async pipe subscribes, unsubscribes, AND triggers CD on new values
}

5. Manual Change Detection Control

export class ManualCDComponent {
  private cdr = inject(ChangeDetectorRef);

  // markForCheck() — mark this component AND ancestors for checking
  // Used with OnPush when data changes outside normal triggers
  updateFromWebSocket(data: any) {
    this.data = data;
    this.cdr.markForCheck();  // "Hey Angular, check me next cycle"
  }

  // detectChanges() — run CD immediately for this component + children
  // Synchronous — updates DOM right now
  forceUpdate() {
    this.someValue = computeExpensiveValue();
    this.cdr.detectChanges();  // Update DOM NOW
  }

  // detach() — completely remove this component from CD tree
  // reattach() — add it back
  // Use for components that rarely change (e.g., static header)
  ngOnInit() {
    this.cdr.detach();  // Never checked automatically

    // Only check when specific observable emits
    this.dataService.criticalUpdates$.subscribe(data => {
      this.data = data;
      this.cdr.detectChanges();
    });
  }
}
Performance Anti-patterns:
  • Calling detectChanges() in a loop
  • Function calls in templates: {{ getFullName() }} — recalculated EVERY CD cycle
  • Complex expressions in templates: {{ items.filter(x => x.active).length }}
  • Not using trackBy/track with *ngFor/@for

6. Zoneless Angular (Angular 18+)

The Future: No Zone.js

// app.config.ts — Enable zoneless mode
import { provideExperimentalZonelessChangeDetection } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [
    provideExperimentalZonelessChangeDetection(),
    provideRouter(routes),
    provideHttpClient()
  ]
};

// Benefits:
// 1. Smaller bundle (Zone.js removed — ~13KB gzipped saved)
// 2. Faster startup (no monkey-patching)
// 3. Better debugging (no Zone.js stack frames)
// 4. More predictable CD (only when signals/async pipe change)
// 5. Better SSR performance

// How it works without Zone.js:
// Angular tracks reactivity through SIGNALS
// When a signal changes, Angular knows exactly which components to update
// No need to check the entire tree

@Component({
  template: `
    <h1>{{ name() }}</h1>        <!-- Signal in template -->
    <p>Count: {{ count() }}</p>
    <button (click)="increment()">+</button>
  `
})
export class ZonelessComponent {
  name = signal('Angular');
  count = signal(0);

  increment() {
    this.count.update(c => c + 1);
    // Angular automatically detects signal change and updates DOM
    // No Zone.js needed!
  }
}

7. Lazy Loading & Code Splitting

Route-level Lazy Loading

// app.routes.ts
export const routes: Routes = [
  { path: '', component: HomeComponent },
  {
    path: 'dashboard',
    loadComponent: () => import('./features/dashboard/dashboard.component')
      .then(m => m.DashboardComponent)
  },
  {
    path: 'admin',
    loadChildren: () => import('./features/admin/admin.routes')
      .then(m => m.ADMIN_ROUTES),
    canActivate: [authGuard]
  },
  {
    path: 'reports',
    loadComponent: () => import('./features/reports/reports.component')
      .then(m => m.ReportsComponent),
    // Route-level providers (scoped to this route and children)
    providers: [ReportsService]
  }
];

// admin.routes.ts (child routes)
export const ADMIN_ROUTES: Routes = [
  { path: '', component: AdminDashboardComponent },
  { path: 'users', loadComponent: () => import('./users/users.component').then(m => m.UsersComponent) },
  { path: 'settings', loadComponent: () => import('./settings/settings.component').then(m => m.SettingsComponent) }
];

Preloading Strategies

import { PreloadAllModules } from '@angular/router';

// Preload ALL lazy routes after initial load
provideRouter(routes, withPreloading(PreloadAllModules))

// Custom preloading strategy
@Injectable({ providedIn: 'root' })
export class SelectivePreloadStrategy implements PreloadingStrategy {
  preload(route: Route, load: () => Observable<any>): Observable<any> {
    // Only preload routes marked with data: { preload: true }
    return route.data?.['preload'] ? load() : of(null);
  }
}

// Route config
{ path: 'dashboard', loadComponent: ..., data: { preload: true } }  // Will preload
{ path: 'admin', loadComponent: ..., data: { preload: false } }     // Won't preload

@defer — Deferrable Views (Angular 17+)

<!-- Lazy-load a component only when visible in viewport -->
@defer (on viewport) {
  <app-heavy-chart [data]="chartData" />
} @loading (minimum 200ms) {
  <app-skeleton-chart />
} @placeholder {
  <div class="chart-placeholder">Chart will load when scrolled into view</div>
} @error {
  <p>Failed to load chart component</p>
}

<!-- Trigger options: -->
@defer (on viewport)           <!-- When element enters viewport -->
@defer (on interaction)        <!-- On first click/focus/input -->
@defer (on hover)              <!-- On mouse hover -->
@defer (on idle)               <!-- When browser is idle -->
@defer (on timer(5s))          <!-- After 5 seconds -->
@defer (on immediate)          <!-- Next tick (still lazy-loaded chunk) -->
@defer (when condition)        <!-- When expression becomes true -->
@defer (on viewport; prefetch on idle)  <!-- Prefetch chunk on idle, render on viewport -->

8. Virtual Scrolling & Large Lists

// Install: ng add @angular/cdk
import { ScrollingModule } from '@angular/cdk/scrolling';

@Component({
  imports: [ScrollingModule],
  template: `
    <!-- Only renders visible items + buffer -->
    <cdk-virtual-scroll-viewport itemSize="48" class="list-viewport">
      <div *cdkVirtualFor="let item of items; trackBy: trackById" class="list-item">
        {{ item.name }}
      </div>
    </cdk-virtual-scroll-viewport>
  `,
  styles: [`
    .list-viewport { height: 400px; width: 100%; }
    .list-item { height: 48px; display: flex; align-items: center; }
  `]
})
export class VirtualListComponent {
  items = Array.from({ length: 100000 }, (_, i) => ({ id: i, name: `Item ${i}` }));
  trackById = (index: number, item: any) => item.id;
}

10. Performance Checklist

✅ Angular Performance Checklist

  1. OnPush everywhere — Set ChangeDetectionStrategy.OnPush on ALL components
  2. Async pipe — Use in templates instead of manual subscriptions
  3. track in @for — Always provide a unique identifier
  4. No function calls in templates — Use pipes, computed signals, or memoization
  5. Lazy load routes — Split bundle by feature
  6. @defer for heavy components — Load on viewport/interaction
  7. Virtual scrolling — For lists > 100 items
  8. RunOutsideAngular — For animations, scroll handlers, resize observers
  9. Pure pipes — Over impure pipes or template functions
  10. Preloading strategy — Preload critical routes on idle
  11. Image optimization — NgOptimizedImage directive
  12. Bundle budgets — Set warnings in angular.json
  13. Signals — Use computed() instead of getter functions
  14. Detach rarely-changing components — cdr.detach() for static UI
