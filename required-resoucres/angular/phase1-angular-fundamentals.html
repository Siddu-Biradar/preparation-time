1. Angular History & Evolution

📺 YouTube Tutorials
  • Angular in 100 Seconds — Fireship
  • Angular Course for Beginners — Programming with Mosh

Theory

AngularJS (2010): Created by Miško Hevery at Google. Two-way data binding, MVC architecture. Written in JavaScript. Had performance issues with large apps due to dirty checking ($digest cycle).

Angular 2+ (2016): Complete rewrite. TypeScript-based, component architecture, unidirectional data flow, ahead-of-time compilation. No backward compatibility with AngularJS.

VersionYearKey Features
Angular 22016Complete rewrite, TypeScript, Components, Modules, DI
Angular 42017Smaller bundles, Animation package, *ngIf else
Angular 52017Build Optimizer, HttpClient, AOT by default
Angular 62018Angular Elements, Tree-shakable providers, ng update/add
Angular 72018Virtual Scrolling, Drag & Drop, Bundle budgets
Angular 82019Differential Loading, Lazy loading with import(), Ivy preview
Angular 92020Ivy renderer default, smaller bundles, faster testing
Angular 10-122020-21Strict mode, Tailwind support, Nullish coalescing in templates
Angular 132021View Engine removed, IE11 dropped, dynamic components simplified
Angular 142022Standalone Components, Typed Reactive Forms, inject() function
Angular 152022Standalone APIs stable, Directive composition API, Image directive
Angular 162023Signals (developer preview), Required inputs, SSR improvements
Angular 172023New control flow (@if, @for, @switch), Deferrable views (@defer), New branding
Angular 182024Zoneless change detection (experimental), Stable signals
Angular 192024Incremental hydration, Resource API, linkedSignal
Key Insight: Angular follows semantic versioning with major releases every 6 months. The framework has evolved from heavy module-based architecture to lightweight standalone components with signals-based reactivity.

2. Angular Architecture Overview

The Big Picture

Angular is an opinionated, batteries-included framework — unlike React (library), Angular provides everything out of the box: routing, forms, HTTP client, testing utilities, animations, i18n, and build tooling.

How Angular Bootstraps

// main.ts (Modern Angular 17+)
import { bootstrapApplication } from '@angular/platform-browser';
import { AppComponent } from './app/app.component';
import { appConfig } from './app/app.config';

bootstrapApplication(AppComponent, appConfig)
  .catch(err => console.error(err));

// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(),
  ]
};

Bootstrap Flow (What happens when Angular app loads)

  1. Browser loads index.html — Contains <app-root> placeholder
  2. main.ts executes — Calls bootstrapApplication() or platformBrowserDynamic().bootstrapModule()
  3. Angular creates platform — Sets up Zone.js, change detection, DI container
  4. Root component instantiated — AppComponent created, template compiled
  5. Component tree renders — Recursively creates child components
  6. Change detection runs — Initial data binding, DOM updated
  7. App is interactive — Event listeners attached, Zone.js monitoring
Interview Gold: "Angular uses a hierarchical dependency injection system where each component can have its own injector. The component tree parallels the injector tree."

4. NgModules vs Standalone Components

NgModules (Legacy but still in production codebases)

@NgModule({
  declarations: [    // Components, Directives, Pipes OWNED by this module
    UserListComponent,
    UserCardComponent,
    HighlightDirective,
    TruncatePipe
  ],
  imports: [         // Other modules whose exports this module needs
    CommonModule,
    FormsModule,
    RouterModule.forChild(routes)
  ],
  exports: [         // What other modules can use when they import this module
    UserListComponent,
    UserCardComponent
  ],
  providers: [       // Services available in this module's injector
    UserService
  ]
})
export class UsersModule { }

Standalone Components (Modern Angular 14+)

@Component({
  selector: 'app-user-list',
  standalone: true,    // No NgModule needed!
  imports: [           // Directly import what you need
    CommonModule,
    UserCardComponent,
    HighlightDirective,
    TruncatePipe,
    RouterLink
  ],
  template: `
    <div *ngFor="let user of users">
      <app-user-card [user]="user" />
    </div>
  `
})
export class UserListComponent {
  users = inject(UserService).getUsers();
}
When to use what:
  • New projects (Angular 17+): Always use standalone components. No NgModules needed.
  • Existing projects: Gradually migrate to standalone. Both can coexist.
  • Libraries: Still use NgModules for backward compatibility (or provide standalone exports).

Key Differences

AspectNgModuleStandalone
Declarationdeclarations: [...] in modulestandalone: true in component
DependenciesModule imports shared across all declarationsEach component imports its own deps
Tree-shakingEntire module bundled if any part usedOnly used components bundled
Lazy LoadingloadChildren: () => import(...).then(m => m.Module)loadComponent: () => import(...)
BoilerplateHigh (module file per feature)Low (component is self-contained)

5. Components — The Building Blocks

Component Anatomy

import { Component, Input, Output, EventEmitter, inject } from '@angular/core';
import { CommonModule } from '@angular/common';

@Component({
  selector: 'app-user-card',          // CSS selector for this component
  standalone: true,
  imports: [CommonModule],
  templateUrl: './user-card.component.html',  // or inline template
  styleUrls: ['./user-card.component.scss'],  // or inline styles
  // Encapsulation modes:
  encapsulation: ViewEncapsulation.Emulated,  // Default — scoped CSS
  // ViewEncapsulation.None — global CSS
  // ViewEncapsulation.ShadowDom — real Shadow DOM
  changeDetection: ChangeDetectionStrategy.OnPush  // Performance optimization
})
export class UserCardComponent {
  // Inputs — data from parent
  @Input({ required: true }) user!: User;
  @Input() showAvatar = true;

  // Outputs — events to parent
  @Output() selected = new EventEmitter<User>();
  @Output() deleted = new EventEmitter<string>();

  // Dependency Injection
  private readonly userService = inject(UserService);

  // Methods
  onSelect(): void {
    this.selected.emit(this.user);
  }

  onDelete(): void {
    this.deleted.emit(this.user.id);
  }
}

6. Component Lifecycle Hooks

Complete Lifecycle (in execution order)

HookWhen CalledUse Case
ngOnChanges()Before ngOnInit AND every time @Input changesReact to input changes, compare previous/current values
ngOnInit()Once, after first ngOnChangesInitialize data, API calls, setup subscriptions
ngDoCheck()Every change detection cycleCustom change detection logic (USE CAREFULLY — runs very often)
ngAfterContentInit()Once, after ng-content projectedAccess @ContentChild references
ngAfterContentChecked()After every check of projected contentReact to projected content changes
ngAfterViewInit()Once, after view (template) initializedAccess @ViewChild, DOM manipulation, 3rd party lib init
ngAfterViewChecked()After every check of viewReact to view changes (USE CAREFULLY)
ngOnDestroy()Before component is destroyedUnsubscribe observables, detach event listeners, cleanup

Lifecycle in Code

export class UserProfileComponent implements OnInit, OnChanges, OnDestroy, AfterViewInit {
  @Input() userId!: string;
  @ViewChild('chart') chartElement!: ElementRef;

  private destroy$ = new Subject<void>();
  user: User | null = null;

  private userService = inject(UserService);

  // 1. Called BEFORE ngOnInit and on every @Input change
  ngOnChanges(changes: SimpleChanges): void {
    if (changes['userId'] && !changes['userId'].firstChange) {
      // Input changed after initialization — reload data
      this.loadUser(changes['userId'].currentValue);
    }
    // Access previous value:
    // changes['userId'].previousValue
  }

  // 2. Called ONCE after first ngOnChanges
  ngOnInit(): void {
    this.loadUser(this.userId);
  }

  // 3. Called ONCE after template is rendered
  ngAfterViewInit(): void {
    // Safe to access @ViewChild here
    this.initChart(this.chartElement.nativeElement);
  }

  // 4. Called when component is destroyed
  ngOnDestroy(): void {
    this.destroy$.next();
    this.destroy$.complete();
  }

  private loadUser(id: string): void {
    this.userService.getUser(id)
      .pipe(takeUntil(this.destroy$))
      .subscribe(user => this.user = user);
  }
}

🎯 Interview Question: What's the difference between constructor and ngOnInit?

Constructor: TypeScript/JavaScript class feature. Called when class is instantiated. DI happens here. At this point, @Input values are NOT yet available (they're undefined). Use only for DI.

ngOnInit: Angular lifecycle hook. Called AFTER Angular sets @Input properties. Use for initialization logic, API calls, setting up subscriptions.

export class MyComponent implements OnInit {
  @Input() data!: string;  // undefined in constructor!

  constructor(private service: MyService) {
    console.log(this.data); // undefined ❌
  }

  ngOnInit() {
    console.log(this.data); // has value ✓
    this.service.load(this.data);
  }
}

7. Decorators & Metadata

What are Decorators?

Decorators are TypeScript features (stage 3 proposal in JS) that Angular uses extensively. They are functions that modify classes, properties, methods, or parameters by adding metadata that Angular reads at compile time.

Class Decorators

@Component({...})    // Defines a component
@Directive({...})    // Defines a directive
@Pipe({...})         // Defines a pipe
@Injectable({...})   // Marks class for DI
@NgModule({...})     // Defines a module (legacy)

Property Decorators

@Input()             // Accept data from parent
@Input({ required: true, transform: booleanAttribute })
@Output()            // Emit events to parent
@ViewChild(ref)      // Access child component/element
@ViewChildren(ref)   // Access QueryList of children
@ContentChild(ref)   // Access projected content
@ContentChildren(ref)// Access QueryList of projected content
@HostBinding('class.active')  // Bind to host element property
@HostListener('click', ['$event'])  // Listen to host events

How Decorators Work Under the Hood

// What @Component actually does (simplified):
function Component(metadata: ComponentMetadata) {
  return function(target: Function) {
    // Attaches metadata to the class
    Reflect.defineMetadata('annotations', metadata, target);
    // Angular compiler reads this metadata to:
    // 1. Generate component factory
    // 2. Set up change detection
    // 3. Create template instructions
    // 4. Wire up DI
  };
}

// Generic service
@Injectable({ providedIn: 'root' })
export class StorageService {
  get<T>(key: string): T | null {
    const data = localStorage.getItem(key);
    return data ? JSON.parse(data) as T : null;
  }

  set<T>(key: string, value: T): void {
    localStorage.setItem(key, JSON.stringify(value));
  }
}

9. Compilation: JIT vs AOT

JIT (Just-in-Time) Compilation

  • Templates compiled in the browser at runtime
  • Used during development (ng serve)
  • Slower initial load (compiler shipped to browser)
  • Errors caught at runtime
  • Larger bundle (includes Angular compiler)

AOT (Ahead-of-Time) Compilation

  • Templates compiled at build time
  • Used in production (ng build)
  • Faster initial load (pre-compiled, no compiler in bundle)
  • Template errors caught during build
  • Smaller bundles (compiler tree-shaken)
  • Security: Template injection attacks prevented

What AOT Actually Does

// Your template:
<h1>{{ title }}</h1>
<button (click)="increment()">{{ count }}</button>

// AOT compiles to something like:
function MyComponent_Template(rf, ctx) {
  if (rf & 1) {  // Creation mode
    ɵɵelementStart(0, "h1");
    ɵɵtext(1);
    ɵɵelementEnd();
    ɵɵelementStart(2, "button");
    ɵɵlistener("click", function() { return ctx.increment(); });
    ɵɵtext(3);
    ɵɵelementEnd();
  }
  if (rf & 2) {  // Update mode
    ɵɵadvance(1);
    ɵɵtextInterpolate(ctx.title);
    ɵɵadvance(2);
    ɵɵtextInterpolate(ctx.count);
  }
}
Interview Trap: "Is Angular compiled or interpreted?" — Angular templates are COMPILED (to JavaScript instructions). The rendering is NOT DOM string parsing like innerHTML. This is why Angular is secure against XSS by default — it never uses innerHTML for bindings.
